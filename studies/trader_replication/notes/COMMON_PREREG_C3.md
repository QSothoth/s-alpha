# C3 预登记：只给赢家在新买点加仓（仓位）

2026-10-20，C2 结果出来之前写定（写时 C2 未看到任何一行），跑完不改。

## 机制与依据

诊断里 Martin 有 2 笔“已持有同票”（TSLA 2025-09-10、AMD 2025-10-01 是他在持仓上再买），各人台账里还有 7 行明写的加仓（Minervini SG、SHAK、ALHC，Qullamaggie CVNA、AI 等），都被记成“形态 / 已持有”。METHOD 的尺子：仓位环节的作用是“放大大赢家”。7 人原话都有“只加赢家”：

| | 原话 | 本轮取值 |
|---|---|---|
| Flanders | 在赢家出现新的买点时金字塔加仓；只加赢家；有浮盈垫的赢家可以给更宽的止损 | 0.5 |
| Clement | 顺利才加，加仓不超过原仓位的一半 | 0.5，最多 1 次（三个候选都是） |
| Kell | “if it moves up a little I will add and raise my stop”；理想是“twice as big of a position and I actually have no risk on it” | 1.0 |
| Minervini | 每次加仓本身都要是合格买点；渐进加仓（试水 1/4、1/2） | 0.5 |
| Marios | 只做 free-roll 加仓：加完后全部止损在平均成本上方，总仓位 ≤ 30% | 0.5 |
| Qullamaggie | 1 分钟高点买了，5 分钟高点再加；量价守住再加（ALT） | 0.5 |
| Martin | 按权益百分比加码；新仓顺利才继续加（登记版本已有 +10R / +20R 加码，不动） | 0.5 |

机制：**持仓收盘高于成本、且当天他的买点信号又出现时，按收盘加原仓位的一定比例**（引擎 `add_signal` + 新字段 `add_signal_profit`，入场当天不加；单只上限、总敞口照旧限制加仓量）。信号用各人系统自己的买点掩码。执行时点单测 `tests/test_day_trim_signal_add.py`（只加赢家）、`tests/test_common.py`（开关）。
