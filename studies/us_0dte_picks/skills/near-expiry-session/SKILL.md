# 最近到期期权交互工作流

工程根目录是 `/opt/opend-us-options`。所有模块命令在该目录执行；连接 OpenD 使用 `/opt/futu-opend/venv/bin/python`。先读根 `AGENTS.md`，按任务读 `studies/AGENTS.md` 或 `custody/AGENTS.md`。

安装入口是指向仓库的符号链接；本文相对链接按本文件的真实路径（`realpath`）解析。

## 分工与授权

程序负责可重复检查：真实行情、最近到期日、卡片有效期、预算预留、去重、订单状态、持久化恢复和日志。agent 负责解释候选、理解用户决定、诊断异常、选择授权内的恢复方式、整理证据与提出研究假设。不要在 skill 里重写执行器，或让自然语言判断绕过程序拒绝。

先从会话提取交易日、模式、预算、账户、是否允许新入场、采集截止时间和已授权决策范围。读取实际美东时间；只补问会阻碍下一步的缺失信息，已有且适用的授权不重复确认。新的交易日不默认为延续昨日实盘或后台采集授权。skill 被触发不等于获得下单授权。

同时明确当日买卖权限 `trade_action`：`round_trip` 当日买卖；`buy_only` 只买并保留仓位，连 stop 都不能卖；`sell_only` 只接管已核实持仓，使用 position_pnl_v1 持仓毛收益规则自动择时退出（兼容 stop／尾盘退出），不能买。CLI、持仓移交和限制见 [RUNTIME.md](../../../../docs/RUNTIME.md)。`session accept` 支持前两种；只卖直接走 custody，沿用原数据库，不依赖新入场卡。`HELD` 表示有仓且本次只买任务结束，不是平仓；需要后续交易日明确接管。不能把“今天不买”误解成停止已有只卖任务，也不能把“只买”解释成允许自动止损卖出。只卖需要真实平均成本；缺失时停止接管，不用现价补造。首版只卖候选仅 dryrun/paper，live 尚未获验证；不得绕过该限制。

- “mock”指本地 `dryrun`，不等于 `paper` 券商模拟账户。`paper` 与 `live` 均会发券商委托。
- 当前交接入口固定 `open_hold_v3`、每笔一张、每日每模式最多两个不同标的、总权利金上限 280 美元（300 美元预算减 20 预留）。不同预算先核对并修改工程约束，不能只改口头计划。
- 筛选池固定 11 只科技股；合约检查仅最近五档行权价。选不到可以记录未入场，不能声称全市场无机会。
- v3 有开盘一小时兜底入场；必须区分普通择时与 `deadline_entry`。改变这项产品选择需要明确讨论，不能伪装成故障修复。

## 进入、恢复与汇报

已有 session 时先执行只读入口（替换 SESSION 为确认过的目录）：

```bash
python3 -m studies.us_0dte_picks.session status --session SESSION
```

读取 `now/trade_date`、`service`、卡片、`errors`、`mock`、`handoffs`、`jobs`。顶层 `status` 是观察服务状态，不能覆盖 mock 失败或持仓事实；`mock.fresh=false` 是旧快照，不抹去历史失败。`handoffs/jobs` 范围是该交易日全部 session 与账户，按模式分组，归属结合 ledger 的卡片 hash 核对。没有 session 路径时先查当日笔记和 `data/` 下匹配日期目录；不根据目录名字猜是否实盘。

用户问“怎么样了”，用新读取的证据回答：截至何时、是否实际入场、当前仓位／失败原因、下一步。`active` 只代表进程存在，`JOB_CREATED` 只代表任务落库。实际成交需核对同一数据库订单记录；实盘结果有歧义时还要通过现有 custody 的券商对账能力核实。查询失败就说状态未知。

启动观察、接受卡片、查日志与请求退出的准确 CLI 见 [WORKFLOW_CN.md](../../notes/WORKFLOW_CN.md)。先查 `--help` 或源码确认参数，不复制历史日期直接执行。

1. 盘前已有授权时用 `prepare_watch` 冻结输入，再用 `launch_watch` 核验与有限期启动。`prepare_watch` 仅限 09:30 前；盘中没有合格的当天冻结输入时，记录条件缺失，不用未来数据补造开盘判断。
2. 有新卡时向用户解释标的、方向、最近到期日、报价时间、价差、预算和入场原因；需要用户决策才提问。用户已授权 agent 在明确范围内选取时可按该范围推进，不再逐张索要同意。
3. 交接统一走 `session accept`：先预览，执行时显式模式；`paper/live` 必须明确账户。执行前有适用授权即可，不重复确认。预览不锁卡，过期必须放弃，不能延长有效期追单。
4. 成功后再次查状态和成交证据。round_trip / sell_only 的观察截止不会结束 custody 持仓管理；持续管理沿用原数据库，不创建新任务代替恢复。buy_only 的 `HELD` 按上述权限结束当日管理并保留持仓。

当前工具自动完成交接前 dryrun 和实时复核，但没有保证开盘前整个未来交接必然成功。启动后检查 ready 与首个业务输出；首次真实交接后立即核验。后台写文件不代表 agent 会被自动唤醒或主动通知，明确实际监控进程、截止时间和下一次检查安排。

## Mock 与取消

已获有限期 mock 授权且当日只读 monitor 有效时，可以运行：

```bash
/opt/futu-opend/venv/bin/python -m studies.us_0dte_picks.mock_watch --session SESSION --until 16:05
```

它在 10:45 前自动接受新鲜卡，只调用 dryrun；需要新的 `mock/` 输出目录。截止时间必须仍在当天未来且不晚于 16:10。需要后台运行时沿用项目 systemd 方式，明确 `User`、工作目录、UTF-8、内存与时限，保存 unit 名以便追踪；不要新建无限重试守护进程。结束时它停止自己拥有的 dryrun worker，并记录未完成任务，不能把 `finished` 当作全部平仓。

“今天不交易”立即撤销后续入场安排：核对并停本 session 的扫描／自动交接进程，保留取消记录；已发委托与已有持仓通过 custody 受控处理，不能用停止 worker 代替撤单或退出。不要顺便启动 mock，除非已授权。后续明确允许 mock 时仅恢复 dryrun 范围。

## Agent 异常处理边界

| 证据 | 处理 |
|---|---|
| 行情断连、旧报价、缺分钟 | 明确数据缺口；可在原授权与截止时间内有限重试只读查询（同一故障最多两次），仍失败则停在不可执行状态并报告。不估造报价、不自动扣新历史额度。 |
| 预检失败，尚无预留／任务 | 读日志定位，修复环境并离线验证；只在卡仍新鲜、授权有效时重试。卡已过期则记录错过，不补写成交。 |
| 已有 RESERVED、任务或委托结果不明 | 保留预算锁、原 DB 与 job 身份，先对账。不得删 ledger、换 DB 或换 session 绕过去重；未消除歧义不发新订单。 |
| worker 异常且有持仓 | 优先核实券商与原任务状态，恢复原任务管理；需要用户处置时给出具体未决状态，不静默搁置。 |
| 代码需要修复 | 授权内的小修可以做并跑相关测试；有持仓时先保护原任务，不热换策略。策略行为改动按仓库新版本与评测流程处理。 |

每次异常保留时间、阶段、原始错误、是否有任务／订单／持仓、采取的动作、恢复后证据及剩余问题，写入 session 事件记录或当日笔记。不要把失败重命名为“等待信号”。当前工具没有全自动故障分类或券商对账总入口，agent 必须查现有日志／custody 能力，不能声称已自动兜底。

## 复盘与经验积累

按 [TRADING_OBSERVATION_CN.md](../../notes/TRADING_OBSERVATION_CN.md) 复盘选择、等待、成交、持有与退出。将经验落实为可追溯证据和下一轮验证，而不是宣称自己产生交易直觉。

- 分开呈现实际成交、本地模拟成交、未成交机会的反事实；无成交就没有这笔已实现交易收益。
- 真实买入成本和可卖 bid 估值要标时间、新鲜度及手续费口径；观察峰值不是可实现最高收益，数据断档不是完整最大回撤。
- 报告输入→卡片→预检→交接→成交→退出的耗时与失败点，再判断应补工程约束、agent 操作规则还是策略研究。
- 最近到期执行已支持，不代表 v3 的当日到期估值模型已适配。退出研究先读 [OH3_EXIT_AUDIT_CN.md](../../reports/OH3_EXIT_AUDIT_CN.md)，注册表是当前策略状态依据。
- 昨天的新想法先预登记假设与门槛，再找未使用数据验证；不按单笔走势调整止损、追溯填单或改写旧报告。
