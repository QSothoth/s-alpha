# R29：两种交易 mode 的历史基线审计

2026-10-14，用户要求后续同时考虑自由择时和必须交易，并先算旧策略基线。本轮不选新参数、不晋级任何策略，九个已注册版本属于历史基线，不是九个新候选。

- `selective`：无信号可以不买；一旦买入，当天退出，一次买入一次卖出。
- `required`：当天选定合约必须安排一次买入和卖出；信号入场未发生时使用既有截止时间兜底，尾盘发出退出。以实际完成判定，期权无后续成交而按到期内在价值结算不算卖出完成。
- 现有 zero_dte_timing_v6.1–v6.6 属于 selective；open_hold_v1–v3 属于 required。V6.6 与 open_hold_v2 的离场相同，后者加 60 分钟兜底，可对照兜底本身的影响；open_hold_v3 是历史保证入场线的基线，离场另有差异，不能把收益差全归于 mode。
- 重放已有开发集 custody-0dte-v6.1，逐 case 调用原评测器的 run_strategy 作一致性审计，不产生新策略评级；每个主口径交易逐字段与已经由官方 evaluate 生成的报告对照。然后重算分侧与入场/退出原因统计。只使用现有开发数据，不打开 SV1 或新的验证数据。
- 报告完整买卖数、未入场/未成交/到期结算、信号入场/兜底、主动退出/尾盘、持有时长、方向平衡净收益/盈亏比/综合分、CALL/PUT 分侧原始及平衡收益。分侧覆盖缺口必须披露。
- 本数据为 21 日、73 个标的日、146 个 CALL/PUT case，两个方向是供上游选择的备选，不能把两个同时买入或多标的累计笔数称作单账户一天一次的收益。没有唯一的逐日上游选择，暂不构造账户曲线或从回测结果挑方向。
- 时间损耗已包含在真实期权成交模型的净收益里。额外审计持仓分钟、买卖时刻、到期结算数；报告同步分钟期权收盘减内在价值的入场/退出残余价值变化，它同时包含波动率、价内外程度、报价等影响，不命名为纯 theta，不重复扣减收益。负残余照记，不修成零。
- 后续新机制研究需预先同时冻结两个 mode 的入场和退出，在两个 mode 各自比较基线、单列 CALL/PUT，不能用减少交易或另一 mode 的优点掩盖失败。required 需要在可执行样本中完整买卖覆盖，失败单列不删除；selective 报告参与率与未入场零贡献。现阶段只是研究约束，未新增 runtime CLI mode、未改变默认策略或既有评测门槛。

逐 case 读取和处理，不保留全量行情。记录输入指纹、策略/脚本哈希、资源和对照结果。所有测试与数据质量检查沿用仓库要求。
