# TK9 预登记：借鉴加密货币日内机器人的离场

> 编号说明：2026-10-26 应用户要求，“借鉴加密货币机器人的离场”与“信号后怎么买更便宜”两轮对调编号（原 TK10 → TK9，原 TK9 → TK10）。两份预登记的规则、候选、判定都没有改动；对调前两轮都尚未汇报任何结果。

登记时间：2026-10-26，TK8 跑数期间、**看到 TK8 任何结果之前**。实现 `ticket_eval.py --round TK9`，执行时点单测 `tests/test_ticket_eval.py::CryptoExitTimingTests`。数据、成交模型、指标同 [TK8](TK8_PREREG.md)。

## 来源与假设

用户 2026-10-26：加密货币日内自动交易多，止盈止损做法可以参考。取两个常用开源框架里与 TK8 不重复的机制：

- **Freqtrade `minimal_roi`**：止盈目标随持仓时间递减（文档例：0 分钟 4%、20 分钟 2%、30 分钟 1%、40 分钟后 0%=不亏就走）。对 0DTE：时间价值越到后面流失越快，拿不出结果的仓位应逐步降低要求。
- **Hummingbot 三重障碍**（Position Executor）：止损、止盈、持仓时间上限，外加“到激活价才开始的跟踪止损”，先碰到哪条走哪条。
- **Freqtrade `trailing_only_offset_is_reached`**：到偏移利润之前只用初始止损，之后**按价格**从最高可卖价回落固定比例离场（TK7/TK8 是按利润比例）。
- **吊灯止损**（ATR 跟踪）：最高价减若干倍 ATR，按波动自动调宽窄。

## 候选（5 个；入场都用 v6.6；初始止损都是 −50%；平台收盘前 15 分钟平仓不变）

记号同 TK8：g 为可卖价收益，t 为持仓分钟数（当前分钟 − 成交分钟），H 为持仓以来最高可卖价。

| 候选 | 规则 |
|---|---|
| R1 时间递减止盈 | 止盈目标：t < 30 为 +300%；30 ≤ t < 60 为 +200%；60 ≤ t < 120 为 +100%；t ≥ 120 为 +50%；开盘后第 330 分钟（15:00）起为 0（不亏就走）。g ≥ 目标即卖（记 `ticket_roi`） |
| R2 三重障碍 | −50% / +300% / 持仓满 120 分钟卖出（记 `ticket_time_limit`） |
| R3 偏移后按价跟踪 | g 到过 +100% 之前只用 −50%；之后可卖价 ≤ 0.75·H 即卖（从最高价回落 25%，记 `ticket_price_trail`） |
| R4 吊灯止损 | g 到过 +50% 之后，可卖价 ≤ H − 3·ATR 即卖；ATR 为期权 1 分钟 K 线（高 − 低，与前收盘比的真实波幅）最近 14 根的简单平均，用到当前分钟为止已有的 K 线；ATR 为 0（最近 14 根都没有波动）时不启用（记 `ticket_chandelier`） |
| R5 R1 + R3 | 两条都生效，先到先走（Freqtrade 常见配置：ROI 表 + 偏移跟踪） |

对照：A2（−50% / +300%）、K4（−50% / +100%）、TK8 交叉验证选中最多的候选（无论 TK8 是否通过；跑 TK8 前写定）。

## 选择与判定（跑数前写定）

- 选择：40 折留一天交叉验证，每折从 {R1–R5, A2, K4, TK8 主选} 中选 60% 期望最高者。
- 判定（全部满足为“借鉴版成立”）：交叉验证 60% 期望 > 0 且 60% 利润因子 ≥ 1.2；选中最多的是 R1–R5 之一；该候选在选择段上 60% 期望高于 A2、成交笔盈亏比 ≥ 2.0、≥ +200% 占比 ≥ 4%。
- 已用过的验证段照报，不参与判定；所有结论标“已见过的数据”。不调参数、不在本轮内二次修改。
- 多重检验提醒：TK7、TK8、TK9 都在同一份 40 日选择段上比离场，本轮之后离场层不再在这份数据上加轮次，等新数据。
