# TK11 预登记：修正评测标准后重看所有离场

登记时间：2026-10-26，跑数之前（TK1–TK10 结果都已看过）。实现 `ticket_eval.py --round TK11`，正股跟踪单测 `tests/test_ticket_eval.py::UnderlyingTrailTimingTests`。数据、入场（v6.6，占位）同 [TK8](TK8_PREREG.md)。

## 为什么改标准（用户 2026-10-26：“标准肯定有问题，加密货币的日内策略应该领先我们”）

对 TK7–TK10 的反思（[TK8_TK10_RESULTS_CN](../reports/TK8_TK10_RESULTS_CN.md) 之后）：

1. **“方向准确率 60%”加权偏向拿到收盘（已核实）**：方向对错按当天收盘相对正股的走向判（`label_case`），60% 加权放大“收盘走对”的日子。开盘买入拿到收盘实际每笔 −7.1%，60% 口径却是 +9.0%，全场最高。移动止盈要保护的“先顺后反”日子被算作“方向错”而降权。→ **废除 60% 加权作为主指标**。
2. **只看平均每笔**：选“平均最高”偏向少数大赢家；加密货币策略按资金曲线评（回撤、夏普、稳定性）。→ **主指标改为账户口径**。
3. **跟踪放在期权权利金上**：加密货币机器人的跟踪止损跟的是标的价格、距离按标的波动（ATR）设。TK9 把它换算到权利金上，不是原意。→ **新增正股 ATR 跟踪的忠实版本**。
4. **成交模型惩罚紧止损**：1 分钟 K 线、下一根成交、再扣 25% 振幅；跟踪止损都在下跌中触发，吃亏最多；交易所端止损单是逐笔触发。→ **同时报无滑点口径，排序是否翻转要写明**。
5. 入场接近随机（v6.6 样本外不比随机好）：无法在本轮修正（需要用户的历史选股）；结论标“入场为占位”。

## 新标准

**账户口径（主）**：每笔投入相同权利金（1 个单位），每笔盈亏 = 净收益率；按交易日相加得日盈亏，日内不复利。

| 指标 | 定义 |
|---|---|
| 日夏普（主指标） | 日盈亏均值 / 标准差 × √252（无交易的日子记 0） |
| 总收益 | 日盈亏之和（单位：每笔投入） |
| 最大回撤 | 累计日盈亏曲线从高点的最大回落（同单位） |
| 收益回撤比 | 总收益 / 最大回撤 |
| 赚钱周占比 | 按自然周汇总后为正的比例 |

**按实际成交（不加权）**：每笔平均、胜率、盈亏比、利润因子、平均亏损、≥ +200% 占比、TK8 的“留住”与“赚过 50% 又亏”。

**按当天走势类型分开报**（不加权、不合成）：单边顺、单边逆、先顺后反、先逆后顺、震荡，各自的笔数与每笔平均。用来看每种离场在“先顺后反”里是否真的保住了利润、在“单边顺”里付出多少。

**成交口径**：主口径（25% 振幅滑点）与无滑点口径都报；只用主口径选择和判定。

## 选择与判定（跑数前写定）

- 选择：40 折留一天，每折在其余 39 天上从全部 18 个候选里选日夏普最高者，拼接留出日。
- 判定“移动止盈 / 跟踪类成立”（全部满足）：
  1. 交叉验证选中最多的不是 A2、K4（固定止盈止损）；
  2. 交叉验证拼接的日夏普高于 A2 全期日夏普，且最大回撤不大于 A2；
  3. 选中最多的候选在全期上：总收益 > 0、盈亏比 ≥ 1.5（低胜率高盈亏比方向不倒退过多）。
- 同时报：无滑点口径下的排序；已用过的验证段（4 天，只报告）。
- 本轮是换尺子的重算，旧候选参数一律不改；U1–U5 参数为来源中的常见值，不做网格。
