## 1（阻断）K1–K4 全部跑不起来：`stop_ema_only` 不允许盘中成交

`system.py:392-394`：

```python
policy = management.get(kind, rules)
if early and policy.stop_ema_only:
    raise ValueError('EMA-stop-only mode currently requires a close entry')
```

W = P1 + AS + X1，X1 走 `stop_ema_only=True`（全局 `Rules`，不在 `management_by_kind` 里）；P1 是限价盘中成交 → `intraday()` 判 True → `take(early=...)` → `open_pos(early=True)` → 直接抛错。**K1–K4 全都含 W，组 2 五格一格都跑不出**，而组 2 是本轮唯一的“选择”层。

改法（预登记里写死，别到实现时才定）：
- 盘中成交 + `stop_ema_only` 时，成交日盘中只用初始止损（`stop0` 或 P1 规则止损），EMA 止损在**成交日收盘**按当日 EMA 设一次、次日生效（现有 `system.py:838-840` 的 `max(q.stop, level)` 本来就只在收盘更新、次日才检查，语义已正确）；把 `system.py:393` 的抛错改成这个分支，并加单测：成交日低点 ≤ EMA−1% 但 > 初始止损时不得离场。
- 若不想动引擎，就必须把 X1 从 W 里去掉——但那等于放弃本轮唯一的离场层，不建议。

## 2（不可比）P1 的窄止损会把“加仓层”静默吃掉，并让 `ret_invested` 虚高

探针风险 0.25%（`e7_rules` 的 `rules.risk/2`）、`max_position=.25`。P1 的止损是 `min(b 日低点, 0.99·L)` 再压到 `min(5%, ADR/2)`：突破日强时**下限就是 1%**，多数票的宽度会明显低于 ref 的 3.06%。代入 `open_pos`（`system.py:395,404`）：`val = min(.0025·eq/width, .25·eq, room)`；width=1% → 取证仓位正好 25% = 上限。再进 `add_pos`（`system.py:432-442`）：`cap*eq - q.size*price = 0` → `val=0` → 返回，但 `q.sig_adds` 已在 `system.py:439-442` 先加了 1，`add_signal_max=1` 从此不再试。后果三连环：
- W 里相当一部分票**根本没有加仓**，于是 AS 那层（抬止损）对它们无效，K1 与 K3 的差异被系统性稀释；
- 加仓被截断 → `q.invested` 变小 → `ret_invested` 变高 → 选择规则 1 的“按实际投入涨 ≥ 20% 的赢家笔数”对**恰好是加仓被卡掉的那批臂**更容易过；
- 宽度不同 → `trims=(3,5)` 的 3R/5R 价位跟着变（`unit(q)=|fill−stop0|`），P1 的 3%/5% 就等于 ref 的 9%/15%，分批离场时点整体前移，这已经不是“只改入场价”。

改法：① 每个臂都报 `stop_width_median`、`position_capped_share`、`added` 占比、`add 因 max_position/gross 被拒` 计数（`e8_research.extras` 已能算前两个，直接搬）；② 预登记里给 P1 定一条宽度地板（如 `width = max(0.02, ...)`）**或**把所有臂的 `max_position` 抬到加仓能装下（如 .40），二选一，别让上限冒充规则；③ 选择规则 1 换成“加仓发生比例 ≥ ref 的 90%”之外的、不依赖 `invested` 分母的量，或明确写“该条只在加仓比例合格时才读”。

## 3（定义不清）P0 没有追高上限，“止损同 P1 规则但以开盘价为基准”至少三种读法

- P0 = “b+1 开盘 > h[b−1] 就按开盘价买”。这条对任何幅度的跳空都成立：开盘跳 +20% 也买，止损挂在开盘价下方 → 正是 E3/⑤ 被否掉的追高形态，而且会把 P0 的亏损端（首日被扫 / 大幅回吐）算进“入场价”这一层。ref 的盘中分支有 `fill > open*1.03 → chase` 的护栏（`ie47_e1.py:352-354`），收盘分支没有；P0 必须有。
  - 改法：预登记写死 `open ≤ h[b−1]·1.03` 才买，并报“超过 3% 被拒”的笔数与被拒组的 60 日涨幅（不然“P0 更好/更差”分不清是价格还是选到的票不同）。
- “以开盘价为基准”需要各自写清：0.99 因子对谁、`min(5%, ADR/2)` 宽度对谁、宽度是否 ≥1% 不挂对谁。三种基准（开盘价 / `h[b−1]` / 成交价）会给出不同的止损与不同的成交笔数。改法：一行公式写死，例如 `stop = max(min(l[b], open·0.99), open·(1−min(.05, adr[b−1]/200)))`，并说明 `adr` 取 `[b−1]`（挂单当晚已知）。

## 4（先后歧义→归因混淆）P1 的“b+1～b+3 有效”会越出观察期

ref 的观察窗口是 t+1..t+5（`observe=5`），突破日 b 最晚可以就是 t+5；P1 的挂单再放 3 天到 t+8，等于**同时改了“看得更久”**。E9 已记录“合法的日子里，突破当天明显好于之后几天，晚买更差”，所以 P1 的 ΔR 里混了两件事。

改法：预登记二选一写死——主定义用 `b+1 … min(b+3, t+5)`（只在剩余观察期内有效），或保留 3 天但**必须**报 b−t 的分布、挂单到期未成交数、以及“若把窗口截到 t+5 会少多少笔”的对照。顺带写明“宽度过宽不挂”是否消耗观察期（ref 里 `wide_stop` 在 `del watching[j]` 之后，已经消耗，两者要保持一致或显式不同）。

## 5（选择规则漏洞）组 2 五格全押 W，X1 一层错就全灭，没有回退

K1–K5 = W = P1+AS+X1 的五个变体；X1 拆掉的是产生 +1393R（160 笔）的收盘离场，是全套里最激进的一层。若 X1 在日 K 下不成立，五格一起不合格 → 规则 3“无人有资格：不选”→ 本轮拿不到任何 2026 验证，组 1 的十个诊断也进不了选择（写明“诊断，不选”）。这和“先算出上限再决定是否继续”的规范冲突。

改法：预登记加一条**回退选择**（看结果前定，不增加候选数）：若组 2 无合格者，从组 1 里按同一资格 + 同一排序规则选（组 1 的 ref+AS、ref+P1 都是一层改动，比 W 更容易站住）；或把 K5（W+IN）换成 `ref+AS`（⑦ 最贴原话的一层）以保留一条不依赖 X1 的路。

## 6（口径）组 0 的“成交率”是价格上限，不是账户可成交率；60 日涨幅的锚点与末端截断没写

- 挂单成交要与**当天的新触发**抢 `max_new_long=4` / `max_open=11` / `max_gross=2.8`（`take()` 里 `continue`，不写事件；`open_pos` 里“已持仓 / risk 不合法 / 仓位过小”也是静默返回）。P1 的挂单集中在观察期后半段，撞上满仓的概率不低，所以组 0 的价格路径成交率会**系统性高估**覆盖。改法：组 0 明标“价格上限”，另出账户口径漏斗，并把 `open_pos`/`take` 的静默拒绝补成事件（`already_held`、`max_open`、`max_new_long`、`gross_room`、`too_small`），否则“笔数 ≥70%”这条门槛说不清是价格还是名额丢的。
- “买后 60 天涨幅”：成交组与未成交组必须用**同一锚点**（建议都用 b 日收盘），并且 2025 年末的触发没有 60 个交易日前瞻——要写明是丢弃、还是截断到可用天数并单独报样本数，否则那一档涨幅分布是不同长度窗口拼出来的。

## 7（定义不清）RE 的“先碰到止损”没限定干净止损，且绕过选股

- 按字面，“之后先碰到止损”会包含：`gap_stop`（跳空穿止损）、`stop_day0`、以及**已经 trim 过 3R/5R 之后再止损的赢家**。最后一种再买 = 追一个已经涨过的票，与“多次试单”不是一个机制，却会混进 RE 的收益。改法：限定为 `why ∈ {stop, gap_stop, stop_day0}` **且该仓位从未执行过 trim/add**，或至少按“有无 trim”分两行报。
- RE 的再入场不经过 IE47 每晚筛选、不占 3 名上限、不吃 `select_nights` 的 10 晚冷却，等于在池外补仓。改法：单列“RE 带来的笔数 / 占总成交比 / 这些笔的 avgR 与胜率”，并把“RE 挤掉的新信号笔数”（因 `max_new_long`/`max_open` 被拒）计数；否则“笔数补到 70%”可能全靠 RE，而 RE 不是选股能力。

## 8（先后歧义）CS 的“前 2 个交易日”在收盘入场与盘中入场不是同一段；出场价没写死

收盘入场（ref/K2/K3/K4）在成交日 `d0` 没有盘中时段（`entry_book` 的 close 分支 `day_exit=None`），P1/P0 的 `d0` 有盘中、可以当天被扫。CS 又只在 W 上跑（W 是盘中入场）。所以“前 2 个交易日”的起点必须写成“成交日算第 0 天，硬止损覆盖第 0、1 天的盘中（收盘入场第 0 天自然无盘中）”，否则 CS 与“ref 上的一层诊断”不同段，读不出“被扫一下占多少”。

另外“收盘低于初始止损才走”要写死出场价：当日收盘价（市价），`why` 新开一类 `stop_close`，与 `stop` / `gap_stop` 分开统计——因为 −2× 宽度被跳空穿透时出场价可能远差于 −2R，报平均 R 必须分列，不然 CS 的“亏损变小”可能只是把亏损挪进 gap_stop。

## 9（不可比）SL 的 0.3% 按价格计，天然惩罚窄止损臂

0.3% 的价格滑点在 R 上等于：ref（3.06% 宽）0.10R，P1（≈1–1.5% 宽）0.20–0.30R。也就是说 SL 会同时是“成本敏感性”和“反 P1 的杠杆”，若 P1 的优势薄就会被这条构造性抹掉，而报告会读成“P1 不成立”。

改法：SL 改成“止损/跳空离场时按**宽度的 10%**滑点”（或同时报 0.3% 价格版与 10% 宽度版两个数），并且滑点只加在 `stop/gap_stop/stop_day0` 上，不加在 trail/trim/signal 上——后者不是被扫，是主动离场。

## 10（定义不清）IN 的“窄幅日”单位、ADR 索引与内包日条件没写死，且“不消耗观察期”会变成“多看几天”

- `A['adr']` 是**百分数**（`ie47_e1.py:523` 乘了 100），而 `(h/l-1)` 是小数；“振幅 < 0.6 × 前一日 ADR”直接比会错 100 倍。ADR 索引也要写：用 `adr[b−1]` 时它**含 b−1 自己的振幅**（`rolling(...,'mean')` 以 t 结尾），窄幅日会压低自己的分母；要么写死 `adr[b−2]`，要么说明这是刻意的。
- “内包日”两个条件要显式：`h[b−1] ≤ h[b−2] and l[b−1] ≥ l[b−2]`（b−1 收盘已知，无泄漏）。
- “不合格的突破不消耗观察期”等于把触发机会从“窗口内第一次突破”变成“窗口内第一次**合格**突破”，最多 5 次机会。改法：报“被跳过的首次突破次数”、首次合格日相对 t 的天数分布，以及“若仍然消耗观察期”的笔数差；否则 IN 的改善可能只是“看得更久”，而这是 E9 已经量过更差的维度。

## 11（选择规则漏洞）资格只卡笔数与赢家笔数，缺敞口/加仓同质性门槛；`study.gap` 未钉死

- P1 的窄止损 → 单票名义更大（易撞 25% 上限）+ 持有更久（X1）→ 平均 gross、平均持仓数、加仓比例与 ref 结构性不同。仅“报告”这一项不够：收益排序第一名可能只是杠杆或“少做几笔但每笔更大”。改法：把 `平均 gross、平均持仓数、加仓发生比例` 与 ref 的差异（如 ±10%）写成**资格条件**，与笔数门槛并列。
- 规则 2 的 tie-break 用 `study.gap`，但没写用哪个口径。E8 是用 `e8_research.invested()` 包装后的版本（`ret→ret_invested`，分年均值，`per_year/win/avg_win/avg_loss` 四项）。而 `per_year` 已经进了笔数门槛，把它再放进 tie-break 会偏向笔数少的臂。改法：写死“与 E8 同一函数同一口径”，或 tie-break 只用 `win/avg_win/avg_loss` 三项。

## 12（会崩/会错）成交时点用浮点价格相等判定；P1 的宽度与止损 ADR 索引没写死

- `intraday()`（`system.py:289-290`）靠 `e[3] != c[d, j]` 判断是否盘中成交。P1 限价恰好等于当日收盘（或 P0 开盘 = 收盘的十字星）会被判成收盘成交 → 走 `late` 分支 → `take()` 里 `if len(e) > 6 and e[6] is not None and not early: raise ValueError('same-day stop requires a declared or identifiable intraday entry')`，整轮崩在一笔偶发数据上。改法：把 P0/P1 的 kind 放进 `intraday_kinds`（现在 `execution_rules` 对 E5 给的是空元组，`ie47_e1.py:301`），让分类不依赖价格相等；顺带给这两条分支加单测（限价 = 收盘、开盘 = 收盘、开盘跳空低于 L 三种）。
- P1 的宽度 `min(5%, ADR/2)` 与止损里的 0.99 因子，必须写死用 `adr[b−1]`（挂单当晚已知）；任何 `adr[b]` / `adr[成交日]` 都是未来函数。同理加仓保护 AS 用的“加仓日最低价”只能在收盘（`add_pos` 的调用点）读，不得在盘中判断。
