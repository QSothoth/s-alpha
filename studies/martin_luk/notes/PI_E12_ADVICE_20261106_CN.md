# E12 信号层设计（第二位研究者意见）

只读：读了 `notes/RULES_CN.md`、`skills/trader-replication/references/MARTIN_LUK_CN.md`、`notes/trades.csv`（2024–25 的 dated 多头行）、`ie47_e1.py` 的 `select_nights` / `entry_book`（另看了 `filter_night`、`selection` 的 gate 与 `IE47Study` 的字段，因为通道阈值要用到 `A['adr']` / `to20` 的单位），并核对了 `data/martin-luk-cache/industry.json` 是否存在（存在，3433 只，美股行业标签，属于已有缓存，不用拉新数据）。没有跑回测、没有改代码、没有拉数据。

## 0. 结论先说

**现在的系统不是"信号层不够激进"，是结构反了：先选 3 只 → 观察 5 晚 → 等一次"收盘越过前高"。他是一个几十只的名单 + 每天扫描 → 谁今天出形态就买谁。**

三个数字说明这个结构本身抓不到他：

1. **14 笔买到的里 9 笔比他晚 ≥1 天（其中 4 笔晚 ≥2 天，最晚 +3 天）**（rel：I01 +1、I07 +2、I08 +1、I27 +1、I29 +3、I30 +3、I31 +2、I37 +1、O01 +1；只有 I02/I10/I11/J01 是同日，I13 是 −2），14 笔里只有 3 笔是赚的。
2. **16 笔 pool_not_picked 在他买入当天的画像排名中位数约第 22 名**（I09 12/66、I22 13/74、I23 15/72、I34 22/72、I36 13/96、I40 45/88、I41 40/94、S02 36/72……）。每晚只有 3 个新名额，第 9–22 名永远轮不到，轮到时也已经过了他的日子。**这是排序式选股的几何上限，不是画像不够好**（IE42 的精度 45.8% 已经等于池子平均 46.0%，画像基本没在提供信息）。
3. **7 笔他在池中且排名靠前，被"5 天观察到期 + 10 晚冷却"挡掉**（SOUN、IONQ、RGTI×2、ONDS、ASTS、ACHR）。冷却的语义是"用过的票 10 晚不再碰"，而他的原话是反复做同一批主题龙头：RGTI 2025-09-09 与 2025-10-02、AMC 同日两笔、QUBT 同日两笔、TSLA 2026 连续两天。

所以 E12 的核心不是加一个更好的形态，而是换掉**触发方式**：

> 名单每天维持几十只（池子 + 分级 + 题材簇），**每个收盘按通道扫描全名单，谁今天出形态就买谁**（最多 5 笔/晚）；不再有"每晚 3 只新票"、"5 晚观察到期"、"10 晚冷却"。

这一条同时解决"位置晚 1–3 天"（同日收盘买）、"排名 22 名买不到"（不再按排名发名额）、"冷却挡票"（触发驱动天然只在出形态时买，不需要冷却）。

配套的四处（可以一次全改，理由见第 2 节）：

| 改动 | 现在 | E12 |
|---|---|---|
| 成交时点 | 排队次日及之后，收盘确认 | **信号当日收盘**（看板 14:45–15:00 临时扫描，允许） |
| 名单宽度 | 3 只新票/晚 | 池子全宽（约 67 只）→ 每天出形态的 0–5 只 |
| 冷却 / 观察期 | 5 晚到期 + 10 晚冷却 | 无冷却；观察期 10 晚但**不再被"一次失败突破"消费** |
| 并发与名额 | 账户满 2 就不买 | 并发 4 只、单票 ≤30%（他的 3–4 只、25–30%） |
| 排序 | 画像分数为主 | **通道新鲜度为主**，画像只做同分 tiebreak |

## 1. E12 信号层端到端定义（可直接写成代码）

### 1.0 字段（都用日 K，无未来信息）

```python
# A 里已有：open, high, low, close, volume, turnover, raw_close, to20
#          A['adr'] 是百分数（rolling(h/l-1,20,'mean')*100），下文 adr 一律 /100 成小数
e9, e21, e50 = ema(close,9), ema(close,21), ema(close,50)
rng   = high/low - 1
adr   = A['adr']/100                       # 小数
vol20 = roll_mean(volume, 20)              # 用 t-1 及之前算
r5    = close[t]/close[t-5] - 1
r10   = close[t]/close[t-10] - 1
r20   = close[t]/close[t-20] - 1
ext   = close[t]/e21[t] - 1                # 离 21EMA 的伸展
dd10  = 1 - low[t] / max(high[t-10..t-1])  # 距 10 日高点的回撤（不含 t 的高点）
inside(d) = high[d] <= high[d-1] and low[d] >= low[d-1]
upper(d)  = (close[d]-low[d]) / max(high[d]-low[d], tick)   # 收盘在当日 K 线的位置
```

`upper ≥ 0.60` 就是他"收盘强"的日 K 版；`upper ≥ 0.50` 是"没把涨幅还回去"。

### 1.1 池子（只放宽一处 gate，不改其余）

现在 `filter_night` 是四项**全与**：`h4_history ≥ .6 ∧ adr20 ≥ .7 ∧ option_volume ≥ .8 ∧ low20 ≥ .5`。它把 TEM、AMPX、LMND（S03）、CSIQ、SMTC 挡在门外，5/43 笔。

改成 **`h4_history ≥ .6 ∧ 其余三项至少过 2 项`**。全池从约 67 只涨到约 85–100 只（`option_volume` 是流动性代理，ADL 高但期权量小的票正是他的小盘组）。**不再新加任何硬门槛**（"日均成交额 ≥1 亿"在 R 系列已测过无用，"ADR ≥ 5%"已经在 adr20 分位里）。

### 1.2 名单（分级 + 进出 + 题材）

不分"主名单/中等/落后"三张表，用两个布尔量：

```python
leader(t) = e9[t] > e21[t] > e50[t] and close[t] > e9[t]      # 他的"领涨"
mid(t)    = close[t] > e50[t] and not leader(t)               # 他的"中等，周线还好"
```

- **入名单**：任一晚池子通过；或当天的 D1/EP 通道成立（EP 不需要 leader，他的原话是"不看基本面，只看标题"）；或 `r20` 在池内前 10%（周末 leader 扫描）。
- **出名单**：`close < e50` 连续 3 天；或创 20 日新低（`close = min(close[t-19..t])`）；或落后者（非 leader 非 mid）连续 10 晚无信号。
- **买权限**：leader 可买 D1/PB；mid 只可买 EP；落后不进买入候选。
- **题材簇**（"同一题材多只一起出现在扫描里就说明资金在流入"）：
  `theme_count(t)` = 同 `industry` 的池内只数（用已有 `data/trader-screens/cache/industry_us.json`，**backtest 里按 t-1 的池子成员计数**）× 以及 `co_move(t)` = 池内 20 日收益相关系数 ≥ 0.6 且两者 r10 ≥ 10% 的只数。
  排序时用 `co_move`（点对点可算），行业标签只做看板展示。**同题材并发持仓上限 3 只**，不再限"每晚几只"。
- 名单宽度本身当市况：`leader` 只数 < 其 50 日中位数 → 沿用现有 `regime_scale` 减半逻辑（这一层不动，保证可比）。

### 1.3 四个买入通道（日 K 定义，阈值取整数）

**D1a 枢轴突破（他 ④ 的原话直译：内包日/窄幅日 → 越前一日高点）**

```python
tight_prev = rng[t-1] <= 0.5*adr[t-1] or inside(t-1)
coil3      = max(high[t-3..t-1]) / min(low[t-3..t-1]) - 1 <= 1.0*adr[t]
D1a = close[t] > high[t-1]
      and (tight_prev or coil3)
      and upper(t) >= 0.60
      and ext <= 0.10 and r5 <= 0.15        # ⑤ 不追、不买远离均线
```

**D1b 跳空启动（他 ② 盘前放量跳空的日 K 版）**

```python
D1b = open[t] >= high[t-1]*1.02
      and close[t] > open[t] and upper(t) >= 0.50
      and volume[t] >= 1.5*vol20[t-1]       # 见风险 R1：正式版用 15:45 前累计量
      and ext <= 0.15
```

**D1c 第一波新高（"启动第一天"的补集，抓只涨 1–3% 的启动日）**

```python
D1c = close[t] == max(close[t-19..t])       # 20 日收盘新高
      and r10 <= 0.20                        # 但不是已经涨了一段
      and ext <= 0.12
```

D1a/D1b/D1c 就是"启动第一天怎么在日 K 上抓"。注意它**不要求当日涨幅大**：`close > high[t-1]` 可以是 +1.5%（前一日很窄时），这正好对上"他买入当天常只涨 1–3%"。

**EP（他 ④ EP：跳空 ≥10%、靠近前高、越开盘区间高点）**

```python
gap  = open[t]/high[t-1] - 1
EP = gap >= max(0.05, 0.5*adr[t])            # 他的 10% 在我们的 ADR 池用半 ADR 作下限
     and close[t] >= 0.95*max(high[t-20..t-1])   # 靠近前高（显式不含 t 的高点）
     and upper(t) >= 0.50                     # 日 K 版的"越开盘区间高点"
     and volume[t] >= 1.2*vol20[t-1]
     and adr[t] >= 0.05
```

EP 允许 `mid` 与 `option_volume` 只有 0.5 分位的票（这正是 TEM/AMPX 被挡掉的原因）。

**PB 回调（2025 他的主力；9/21 EMA + 更高低点 + 首次回调）**

```python
trend  = close[t] > e21[t] > e50[t] and e9[t] >= e21[t] and e21[t] > e21[t-5]
fresh  = max(high[t-20..t]) in {high[t-5..t]}        # 20 日高点出现在最近 5 天内（首次回调）
deep   = low[t] <= e9[t]  and close[t] > e9[t]       # 探到 9EMA 并收回
shallow= (close[t] < open[t] or upper(t) <= 0.33) and close[t] > e21[t]   # 日内浅回调，日 K 上不破 9EMA
PB = trend and fresh
     and 0.03 <= dd10 <= 0.15
     and low[t] >= min(low[t-3..t-1])                 # 更高低点
     and close[t] > open[t]
     and (deep or shallow)
PB21 = PB 的变体：low[t] <= e21[t] and close[t] > e21[t] and e9[t] > e21[t]
```

两条必须写进定义的解释：

- **`shallow` 是"小时线回调"在日 K 上的唯一诚实翻译。** I17、I21、S02 这类"日线已经伸展、回调只到小时 21EMA"的票，日 K 上根本不碰 9EMA；只有"日线收阴但收在 21EMA 上方、收盘在当日下三分之一"能表达同一件事。不写 `shallow`，2025 的主力形态整块丢掉。
- **`fresh` 是"底部里的第一次回调"的代码化**：20 日高点出现在最近 5 天内 = 刚突破完的第一次回踩，而不是第 4 次。他明确说"alpha 在第一次回踩"。

### 1.4 已经涨过一段的票怎么处理

```python
extended = ext >= 0.20 or r10 >= 0.25
flag3    = all(rng[d] <= 0.6*adr[d] for d in (t-2,t-1,t)) \
           and close[t] <= max(high[t-3..t-1])*(1+0.02)     # high tight flag（I08 那种）
```

- `extended` 时 **D1a/D1b/D1c 全部关闭**（"不买远离均线的"），只允许 EP 与 PB/PB21。
- 唯一例外：`flag3`（连续 3 天窄幅 + 收盘不突破 3 日高点太多）→ 允许 D1a。这直接对上 I08 LMND（两周 +80–90%、连续内包日，他买了）与 I36 RGTI（9EMA 上方 high tight flag + 跳空）。
- 这就是"已经涨过一段的票处理"：**不是禁止，是换成回调/EP/紧凑旗形三个入口**，而不是在 +30% 之后的下一根大阳线收盘追。

### 1.5 触发驱动建簿（E12 的引擎改动）

```python
for t in nights:                        # 每个美股收盘
    fires = [(rank(channel), code) for code in watchlist[t]
             if channel_fires(code, t)]
    fires.sort(key=lambda x: (x.rank, not is_fresh_today(x), -co_move, -to20, -profile))
    picks[t] = [code for _, code in fires[:5]]     # 排序只为截断，不再"排名决定名额"
    entry[t] = close[t]                             # 信号当日收盘成交
```

- 每晚上限 5 笔（不是 3 只新票）；通道优先级 `D1=0, EP=1, PB=2`。
- **无冷却**：同一 code 只要新通道 fire 且距上次离场 ≥1 个交易日就可以再买（RGTI、QUBT、TSLA 的重复）。
- **观察期语义**：保留 10 晚"名单记忆"，但一次失败的突破/追高拒绝**不消耗**名单（对应 `entry_book` 里 `del watching[j]` 的语义要改）；名单过期只由 1.2 的退出条件决定。
- 并发 4 只、单票 ≤30%、每笔风险 0.5%：沿用 R 系列配置，只把"账户满 2"放到 4。
- 止损与离场**这一轮不动**（`max(当日低点, 收盘×(1−min(5%, ½ADR)))`、收盘跌破 EMA21 清仓、+10R 减 30%）。理由见第 2 节第 3 条。

## 2. 你现在的想法哪里太保守、哪里方向错了

1. **"每轮只改一处"在这个层上是错的，不是保守，是测一个没人相信的配置。** 冷却只在"名额制"下才有意义；观察期只在"排到才买"下才有意义；同日收盘买只在"触发驱动"下才安全（否则你每天在名单上按排名买前三名，等于追高）。这三条是一套的，拆开测只会得到"改了没用"的假结论。**一次全改，用 5 个端到端候选比 5 个 LOO 更有信息量。**
2. **"先改位置再改频率"顺序反了。** N_hit 的上限是"这只票今晚能不能进簿"，冷却和名额先把它钉死在 3/晚。位置改对了（同日收盘），但名额仍是 3 + 冷却 10 晚，SOUN/IONQ/RGTI/ONDS/ASTS/ACHR 照样买不到。**频率是上限，位置是质量，先动的应该是上限**；两者一起改更省轮次。
3. **"止损落在阳线中间，次日回落被洗"这个机制故事站不住。** E10 已用 852 笔逐笔重算过：R 不随止损宽度单调改善（0–2% 组 avgR +0.48，4–5% 组 +0.09），压窄止损只是同时压窄赢家的 R。换句话说"被洗"不是止损宽度问题，是**买入价高了 2–3%**（他的成交在被突破的前高附近，我们在当日大阳线收盘）。所以：**别动止损宽度，动入场价。"同日收盘 / 次日开盘"就是这个动作**，不需要新的证据支撑。
4. **"他买入当天只涨 1–3%，所以我们要买小涨幅日"——别写成过滤器。** 那是在 7 个故事上拟合。日 K 能表达的是"**今天收在前一日枢轴上方、且前一日很窄**"，涨幅是结果不是条件。加 `0.01 ≤ 当日涨幅 ≤ 0.03` 这类条件会立刻过拟合。
5. **对放宽池子的犹豫是纯损失。** 5/43 笔被过滤，其中 TEM、AMPX 是典型的他会做的名字（TEM 也是他的原话标的）。gate 改成"3 项过 2 项"几乎零成本。
6. **把 IE42 画像当主排序是方向错误，不是保守。** 精度 45.8% vs 池子平均 46.0%，它没有提供横截面的区分度；而它把"今天刚出形态但 r20 一般"的票压到 15–45 名，正好是他买的那批。**画像降为 tiebreak，主排序改成"今天是否新触发"。**
7. **过度担心 2026 被污染，同时又过度依赖 43 笔。** 两个都不该影响设计：43 笔是行为尺子的分母（不是样本），2026 只需"选定配置后报一次"。真正要防的是"拿 2026 挑候选"，而这只要求候选在 2024–25 上定死，不需要因此少改几处。
8. **没有算上限就先跑账户。** 触发驱动的最便宜的前置检查是：每晚 fire 笔数的分布 + 43 笔在 [d−2, d+1] 内有通道触发的覆盖率。这一项 10 分钟能出，先把候选砍到 2–3 个再跑账户。

## 3. 候选（≤5 个，端到端）与选择规则

五个候选都包含 1.5 的触发驱动建簿、无冷却、并发 4、同日收盘成交；**只有通道组合不同**（这样差异可归因，且每个都是完整系统）：

| 候选 | 通道 | 池子 | 排序 | 一句话 |
|---|---|---|---|---|
| **C1 同日收盘参照** | 现有 D1a（越过前高，无 tight/伸展约束） | 旧（4 项全与） | 画像 | 只改时点与频率，量"同日收盘"这一格值多少 |
| **C2 枢轴日一** | D1a（tight/coil3 + upper≥0.60 + ext≤0.10）+ extended 封锁 | 3 过 2 | 新鲜度 | 他的突破原话 |
| **C3 C2 + EP** | + EP（gap≥max(5%,½ADR)、近 20 日高、upper≥0.50） | 3 过 2（EP 允 0.5 分位） | 新鲜度 | 补回 TEM/AMPX/PL/RCAT 那类 |
| **C4 C3 + PB** | + PB / PB21（首次回调、更高低点、deep/shallow） | 3 过 2 | 新鲜度 + co_move | 2025 主力形态 |
| **C5 C4 + 题材与重复** | + co_move/theme 进排序 + 同题材并发 ≤3 + 允许同名重复 + flag3 例外 | 3 过 2 | 新鲜度 > co_move > to20 | 最贴他（"反复做同一批主题龙头"） |

**选择规则（预登记，只看 2024–25）**

- **Stage 0 可达上限（不跑账户）**：每夜 fire 笔数中位数 ∈ [1, 6]、p90 ≤ 12；他的 43 笔中在 `[d−2, d+1]` 至少一个通道 fire 的**覆盖率 ≥ 50%（≥22/43）**。不达标 → 该候选淘汰，不加名额、不调阈值硬凑。
- **Stage 1 主尺子**：`N_hit` = 他的 43 笔里，我们在他入场 `[d−3, d+1]` 内买入、且这笔**平仓为正**的笔数。要求 **2024 与 2025 各自 ≥ 8**，且 2025 ≥ 2024（不靠 2024 的 1–2 月）。
- **Stage 2 行为保真**（不过就不许看收益）：`|rel|` 中位数 ≤ 1；买到的票里属于他标的的比例 ≥ 25%；**买到的他的票中盈利比例 ≥ 40%**（现在 3/14 = 21%，这是最该动的数）。
- **Stage 3 账户**：2024、2025 都为正；胜过同池随机入场中位数；2024+2025 笔数 ≥ 400（他 423/940，我们先到一半）；胜率 ≥ 15%；`avg_win/|avg_loss| ≥ 4`；报 R≥5 的笔数与占比（凸性不能被平均掉）。
- **定选**：满足 Stage 0–3 的候选里取 `N_hit` 最高；并列取 `min(2024, 2025)` 收益高者。**2026 只在定选后报一次，标注"已污染，仅参考"。**

**每轮必须报的尺子（按顺序）**

1. `N_hit`（分年）、`bought`（买到几笔他的票）、`bought_wins/bought` ← 首要，回答"他 43 笔里我们买到并赚钱的笔数"。
2. `rel` 分布（他的日子 − 我们的日子）、平仓为正的 rel 分布：区分"买晚了"和"买早了"。
3. 每年笔数、胜率、avg_win/avg_loss、R≥5 笔数与 R 集中度。
4. 账户：2024/2025 收益、回撤、同池随机入场分位。
5. 漏斗：`fires/night` 中位数与 p90、名单只数/晚、`expired` / `rejected(chase|wide|account|regime)` 计数、同名重复笔数。
6. 覆盖：43 笔各自落在哪个 stage（bought / fired_not_picked（并给当晚 fire 笔数排名）/ no_fire / filtered / not_in_scope）。

## 4. 未来函数风险（只列 5 条）

- **R1（最重）同日收盘成交 + 全日量能。** `volume[t]`、`to20[t]`、`turnover[t]` 在 15:00 时并不完整。正式版必须二选一：①量能条件只用 `t-1` 及之前（推荐，零争议）；②用 15:45 累计量按当日时间比例年化。**不写清就是买入时用了未来数据。** 同理 `upper(t)`/`close[t]` 要用 14:45–15:00 的快照价，回测里用收盘价代替要在报告里标成"收盘成交假设（含滑点未计）"。
- **R2 同日止损。** 买在收盘、止损用 `low[t]`：`low[t]` 在 15:00 已经发生过，如果模拟器允许"当日低点触发止损"，就等于用买入前 6 小时的行情停损。**必须规定：入场当日不做止损判定，止损从 t+1 开始**（沿用现有 `entry_day_exit_signal` 的口径就要显式检查）。
- **R3 窗口里含未来。** `fresh = 20 日高点出现在最近 5 天`、`PB 的"第一次回调"` 若写成"未来 20 天内只回调 1 次"就是未来函数。所有"次数/首次"必须是**回看窗口**；所有 `max(high[...])` 要显式写清是否含 t。
- **R4 题材标签是当前时点。** `industry.json` 是今天拉的行业名，用它回测 2024 = 幸存者/重分类偏差（公司被重新归类、退市消失）。回测只用 `co_move`（滚动 20 日收益相关，截至 t−1，池子成员按 t−1 计）；行业标签只允许出现在看板，且看板也不参与排序。
- **R5（不是未来函数但同样会骗人）在 43 笔上选通道。** 通道阈值（0.60/0.10/1.0×ADR/5 天内…）如果用"哪组能多命中他"挑出来的，Stage 0–1 的覆盖率就是样本内的。对策：阈值只取整数常识值、**先看 2024 再看 2025**、并在报告里把 2024 与 2025 的 `N_hit` 分开列；不允许出现"只在 2025 有效"的通道进候选。

## 5. 我不确定、想让你定的三点

1. **5 笔/晚够不够。** 他的 940 笔/年 ≈ 3.8 笔/交易日（含加仓与空头）。若把上限设 5 但 fire 中位数只有 1–2，Stage 3 的笔数门槛（≥400/两年）会自然淘汰 C1–C3——那就说明通道太窄，应该加通道而不是放阈值。
2. **C1（旧形态 + 同日收盘）是否算候选。** 它的唯一作用是给"同日收盘"这一格定价。如果你已经相信同日收盘是对的（我认为证据够），可以把 5 个候选换成 C2/C3/C4/C5 + 一个"通道更多但池子更窄"的对照，信息量更大。
3. **并发从 2 到 4 会让账户曲线换一个量级。** 这是频率层，不属于信号层；但"触发但账户满 2"是漏斗里明确的一档，不改就等于给 E12 加了个假上限。我的建议是这一轮一起改成 4，并在报告里单独给一版"并发仍 2"的数字，让读者看到它值多少。
