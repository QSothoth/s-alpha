# 给 pi 的背景与问题：交易员复刻流水线的接口、阶段和卡子怎么设计（2026-11-08）

你不共享我们的对话，请先读这份说明，再读文中列出的文件。

## 背景（一个月的教训）

我们在复刻公开交易员（第一个是 Martin Luk：美股动量波段，低胜率约 22%、盈亏比约 5 倍，2024 年 +283%、2025 年 +970%）。只用日 K，不用分时，不拉新数据。

做了一百多轮，反复兜圈子。根本原因是**流水线没有固定的结构和卡子**：

1. **选股、信号、分配、执行、尺子混在一起改。** 每轮动好几层，坏了分不清是哪层。H1、H2 两轮从头重搭，同时引入了多处翻译错误。
2. **覆盖尺子不管宽度。** 每晚一百多个信号的系统也能报出近 100% 覆盖；拟合数据上的数字被当成了成绩。直到 S0（`studies/martin_luk/reports/S0_CN.md`）才改成"每晚前 K=3 新点名、早期合格夜、留出为主"。新口径下，留出段最好是 65%，目标 80%。
3. **没有市场级 Switch。** 2024–25 的弱势期他 0 段，2026 年弱势期 7 段；模型从没见过他在弱势里怎么做，所以表现时好时坏。用户判断：需要按行情切换（可参考 SMC 的结构判断：BOS / CHoCH、更高的高点和低点），信号层和交易层都要用。各交易员的 Switch 不同（有人做空）。
4. **尺子换过 6 次**（前 5 覆盖 → 预算 → 宽度 → 主升浪 → 纯度 → 记分卡 B），每换一次就重新开轮。

## 用户这次的要求

- 和你对齐：在 trader-replication skill 里，怎么约定**信号期**（选股和点名）、**交易期**（入场、止损、仓位、离场），以及**按市场行情切换**这一块。
- 流程要**尽可能简单**，方便以后复刻其他交易员。
- 要有**给一个交易员建模的必要接口**（facade）：新交易员只要填这几样东西，就能接上共享的流水线、尺子和卡子。
- 覆盖率门槛、行为门槛、不亏底线等，本质上都是**流水线上的一套卡子**，要先对齐，再重新做一遍。

## 想请你回答（中文 markdown，写到 `studies/martin_luk/notes/PI_PIPELINE_ADVICE_20261108_CN.md`）

1. **交易员建模接口（facade）**：最少要有哪几个方法或数据？建议示意：
   - `regime_map`：行情状态 → 他的行为；
   - `universe`：股票池；
   - `signal(night)`：返回当晚的有序点名；
   - `trade_policy`：入场、止损、仓位、离场。

   每个方法的输入输出、哪些必须由交易员提供、哪些由共享层提供。怎样和现有 `systems.py` / study 模块兼容，不推倒重来。
2. **市场行情 Switch 放在哪**：共享的行情状态模块应该输出什么（离散状态？置信度？），由谁消费；信号层和交易层各自怎么用。怎样避免"拟合行情"本身变成过拟合（三年里行情段很少）。SMC 一类的结构判断放进来是否合适、怎么放最简单。
3. **流水线阶段和卡子**：按顺序列出阶段，例如：
   - 资料与台账
   - 行情 Switch 有效性
   - 信号覆盖
   - 行为与盈亏比
   - 账户
   - 冻结

   每个卡子写清测什么、用哪段数据、通过线、不过时怎么办。要求：上游卡子不过，不许去优化下游；每轮只改一层；检验按行情段留一还是按年份留一，你怎么看。
4. **哪些现有规定应该删掉或合并**：现在 SKILL / METHOD 里口径太多，容易让人迷路。
