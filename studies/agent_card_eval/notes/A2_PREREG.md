# A2 预登记：让审卡不再砍掉右尾

2026-10-02，运行前写定，之后不改。用户要求在 A1 失败后"想办法提升"，暂不考虑各 harness 的耗时差异；费用沿用 A1 的决定，只用 Codex（订阅额度）。

## A1 的失败机制（选择依据，只来自训练集 v6.1）

Codex 拒绝了 91% 的卡，22 张赚钱的卡只接受 1 张，拒绝理由集中在"量能不足、前有阻力、仍在区间"。v6.6 胜率 23%、盈亏比 4.55，利润全靠少数大单；审卡者不知道这个结构，就按"图形是否干净"判断，系统性地砍掉右尾。

## 候选（4 个，均为 Codex gpt-6.1-sol）

| 候选 | 改动 | 结构性理由 |
|---|---|---|
| B1 | 提示里告诉 agent 规则的收益结构（训练集：胜率约 23%，平均赚约为平均亏的 4.5 倍，平均每笔约 +6% 权利金），并改成"默认接受，只有卡片上有具体证据说明这一笔明显差于规则平均水平才拒绝" | 把决策从"是否好看"改成"是否差于基准"，拒绝要有理由 |
| B2 | 同 B1 的背景说明，但不让 agent 做取舍，只给"这一笔走出大行情（权利金翻倍）的概率"；按概率排序，固定拒绝最低的 25% | 排序比二选一信息多；拒绝比例取常见值，不搜索 |
| B3 | B1 + 卡片附上确定性计算的摘要（相对 VWAP、开盘区间、日内高低位置、离强平分钟、1m ATR、近 5 分钟量比、SPY 同向与否） | 让模型少读几百行原始 K 线，减少凭局部形态下结论 |
| B4 | B1 + 推理强度 high（`-c model_reasoning_effort="high"`） | 检验是否只是想得不够 |

摘要字段只用决策分钟及以前的已完成 K 线，方向按期权符号化（"有利方向为正"）。

## 数据

- **选择段**：`custody-0dte-v6.1` 的 96 张卡（A1 已看过结果，只用来挑候选）。
- **验证段**：`or-alpha-2026-09-25-holdout-work`（2026-09-25，52 个合约，从未评测）上 v6.6 的入场卡，只评测一次，不调参。
- `custody-eval-2026-09-18-v2` 的 12 张：A1 已看过结果，只报告。
- 每张卡每个候选 3 次，多数票；B2 取 3 次概率的平均值排序。

## 选择与通过规则

1. 选择段上每个候选算接受部分的合计盈亏（每笔 100 美元），与"全部接受"（+612 美元）比较。
2. **只有合计高于全部接受的候选才有资格**；在有资格的候选里取合计最高者，并列取改动最少者（B1 < B2 < B3 < B4）。都没有资格则本轮失败，不跑验证段。
3. 胜者在验证段跑一次：**合计盈亏 ≥ 全部接受**为通过。验证段只有一个交易日，即使通过也只算"值得前向验证"，不改实盘流程；同时报告相对随机挑同样张数的 p 值。

## 限制

- 选择段是 v6.6 的样本内数据，A1 又看过它的结果；验证段只有一天。
- 给 agent 的收益结构数字来自选择段，验证段上实际结构可能不同。
- 只测 Codex，不能推广到其他 harness。
