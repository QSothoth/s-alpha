# 交易员系统的统一数据层、门禁与比对

适用于 [trader-replication](../skills/trader-replication/SKILL.md)（复刻研究）和 [trader-screens](../skills/trader-screens/SKILL.md)（看板实际运行）。目的只有一个：所有交易员在同一份数据、同一个区间、同一个引擎上跑，结果才能互相比。2026-10-19 定，同日按 Codex 审查修订。

## 1. 数据层

| 项 | 规定 |
|---|---|
| 数据集 | `data/trader-data-v1`（登记在 [DATA.md](DATA.md)，GitHub Release [trader-data-v1](https://github.com/QSothoth/s-alpha/releases/tag/trader-data-v1)，解压到 `data/` 即可）。研究不再各自拉数、各自建缓存 |
| 取数管线 | `studies/trend_breakout/fetch.py`：美股、港股走 OpenD `get_cur_kline`，A 股走新浪；存不复权日 K + 公司行动。和趋势扫描、看板每日 `refresh` 是同一条管线 |
| 面板 | `studies/trader_data/panel.py` 按公司行动前复权，看板和研究共用（见第 4 节）。源数据里收盘或开盘落在当日最高—最低之外的坏 K 线（港股 146 根，美股 0 根），把最高 / 最低扩到包住它们，这会传到 ADR、ATR、形态和止损 |
| 缓存 | 每个面板带“源摘要”（不复权日 K、公司行动、名单三个文件和构建版本的 SHA-256），读取时重算摘要，不一致就重建；缓存在 `data/trader-data/cache/`，按数据集的真实路径命名，软链接和真实路径共用一份 |
| 固定 | `studies/trader_replication/DATA_PIN.json` 记录各市场的源摘要；比对时实际读入面板的摘要必须与它相同（`python -m studies.trader_replication.panels pin us,hk` 在发布数据后写入） |
| 股票池 | 美股 3433 只（现价 ≥ 1 美元、20 日均成交额 ≥ 200 万美元）；港股 505 只（20 日均成交额 ≥ 2000 万港元）；A 股 1697 只（市值 ≥ 100 亿元，不含北交所）。名单按 2026-10 的快照，期间退市的不在内；他们的台账里有些票不在名单里（ETF、后来不在池里的股票），比对表逐个列出。各交易员在此之上按自己的规则再筛 |
| 公共区间 | 数据都从 2023-01-03 开始；2023 年只作指标暖机，评测统一为 2024-01-02 → 2026-10-16（`panels.WINDOW`） |
| 新数据 | 发新 tag（`trader-data-v2` …），旧 tag 不改；换数据集后所有人重跑比对 |

看板默认用 live 模式（第 4 节），名单与研究相同；`--folder` 读其他目录时原样读取。

**系统只有一份**：每位交易员的系统登记在 `studies/trader_replication/systems.py`（研究模块 + 带入配置 + 版本 + 冻结日），横向比对和看板都通过 `studies/trader_replication/runner.py` 运行它；看板每次把回放截到冻结日，与比对表逐年核对。研究改出新配置就登记新版本，冻结要用户同意。

## 2. 门禁

门禁只回答“结果能不能拿来评价”，和策略怎么交易无关，由 `studies/trader_replication/gate.py` 自动检查，单测在 `studies/trader_replication/tests/test_gate.py`。四项都过才算通过：

| 检查 | 内容 |
|---|---|
| 数据 | 实际读入面板的源摘要等于 `DATA_PIN.json` 里的值；净值曲线正好覆盖评测区间内该市场的第一个到最后一个交易日 |
| 不看未来 | 把面板截到 2024-09-30、2025-09-30，截止日及以前喂给引擎的一切——入场的全部字段与顺序、账户规则、规则按名字读取的数组、信号、安慰剂股票池——要与用全量面板时完全一样。只能查出依赖“截止日之后数据”的差异，两个截点之间的局部偷看要靠各规则的执行时点单测 |
| 成交价 | 每一笔交易都有成交记录，每一笔执行价（入场、加码、止损、分批、离场）都在当日最低—最高价之间；期末估值不算执行 |
| 胜率 | 已平仓交易的胜率 ≤ 35%；收益出现非有限值直接不过；不足 30 笔记为“未检查”。这些交易员的系统胜率超过 35%，视为实现或数据有问题 |

止损宽度、盈亏比、安慰剂排位、分年收益都不是门禁：它们属于策略本身，或带有不确定性，只报告。

## 3. 比对与评价

`python -m studies.trader_replication.compare run [us,hk,cn] [交易员 ...]` 把每位交易员当前带入的配置在各市场按同一口径跑一遍，写 `studies/trader_replication/reports/compare.json` 与 `COMPARISON_CN.md`。

- 每格（交易员 × 市场）都记下配置摘要、数据摘要、代码指纹（所跑源码的 SHA-256）、安慰剂种子与次数、numpy 版本；局部重跑时，配置或代码不同的旧格会被丢掉，同一张表不混版本。
- 指标定义集中在 `compare.metrics`：收益按最后一个收盘估值（未平仓不清算）；交易统计只算已平仓，期末未平的另列；年化按日历天数；最大回撤含起始净值 1；利润集中度按盈亏金额；候选数只统计评测区间。
- 安慰剂：各人自己的股票池（前一天收盘确定，含 EP 的人加上 EP 可来自的流动性池，不含当天信号）里随机换股，同一天、同样止损宽度、同样账户规则，100 次、种子固定。
- 等权持有：各市场同一流动性池（美股 ≥ 5 美元且 20 日均成交额 ≥ 2000 万，港股 ≥ 1 港元且 ≥ 5000 万），前一天确定，每日再平衡，不扣成本。
- 每天笔数上限有两种既有写法：Martin R74 在交给引擎前按优先级截断，其余人由引擎按成功开仓数限制。这是各自策略的一部分，没有为统一而改动，表里注明。
- 本人公开成绩照登记列出（Martin 的胜率由他公布的赚亏笔数算出），收益口径和区间常与我们的不一致，好坏由人对照判断，不设自动的收益门槛。

所有数字都是样本内（配置是在同一段数据上逐轮选出的）；冻结后的前向记录是唯一的样本外。复现以 `DATA_PIN.json` 与代码指纹为准；换 numpy 版本后的一致性尚未验证。

## 4. 统一数据接口与实时运行

复刻研究和实际运行都只通过 `studies/trader_data` 取数（说明见其 [README](../studies/trader_data/README.md)），一个开关切换：

| 模式 | 数据 | 用途 |
|---|---|---|
| `frozen`（默认） | 只读冻结 Release（`TRADER_DATA_TAG`，默认 `trader-data-v1`） | 复刻、门禁、横向比对（比对只在 frozen 下运行） |
| `live` | 冻结 Release + `data/trader-live/<版本>/<市场>/` 只追加的增量，自动补到最新收盘 | 看板与冻结系统的实际运行 |

- 两种模式用同一份底座、同一份名单、同一个面板构建；live 只在底座之后追加，底座和已存的增量都不改。
- 补数按需进行，不做定时采集：只缺一个已收盘交易日、且今天还没开盘时，对整份名单取一次快照（美股、港股 OpenD `get_market_snapshot`，A 股新浪列表），几十秒；缺好几天或今天已开盘时，按名单重读这段历史（OpenD `get_cur_kline` / 新浪），美股约 20–30 分钟。都不扣历史 K 线额度。
- 复权：除权当天交易所给的昨收价已按除权调整，它与我们存的不复权收盘价之比就是复权比例；重读历史时用数据源自己的复权因子。
- 补数的检查：快照的昨收价要和我们存的最后收盘价对上（≥ 95% 的股票），重读历史时与已存最后一天的不复权收盘价比较（不一致的股票不超过 1%），否则停止、不写入。
- 收盘前想按收盘价下单时，可用 `provisional=True`：盘中快照当作今天的临时收盘价算信号，不写盘。
- 名单目前固定为冻结时的名单；定期更新名单（新股带加入日期）是 `Dataset` 的扩展点，尚未实现。增量攒够后可打包成新 Release 冻结。
- 尚未实现：live 的“历史不变”门禁（加入新数据后，昨天及以前的决定必须与上次运行相同）和定期用复权接口核对推出的复权比例。

## 5. 空头（多空一体）

2026-10-19 加入。每位交易员的空头按他本人的原话逐人研究，先在研究里过预登记轮次（`S*`）和门禁，用户同意后才在 `systems.py` 登记成新版本（例如 `R6 A5 + S3`）。实现：`studies/trader_replication/shorts.py`；各人的空头形态在自己的研究模块（`short_setups`）。

| 项 | 规定 |
|---|---|
| 市场 | 只在美股研究。港股只有指定证券能沽空，我们没有名单；A 股融券受限：两地只报“不适用”，不调参，多头照常运行 |
| 多头 | 登记版本的多头配置不动；配置里没有 `short` 时 `LongShort` 原样调用研究模块的 build，已登记系统的结果逐位不变 |
| 入场 | 第 t 天收盘确认、收盘卖空，形态只用 t 及以前的日 K；同一天先开多再开空（Martin R53 的 short_last）；空单按 t−1 的 20 日成交额排序，每天最多 `max_new` 笔 |
| 止损 | 在上方：入场当日最高价，至少高出 1%；原话另有规定的照原话（`stop_cap` 只在原话有上限时用）；跳空高开越过止损按开盘价回补，盘中触及按止损价 |
| 离场 | 引擎的空头字段：`short_trims`（按 R 回补一部分）、按形态的跟踪线 / 回补比例 / 单只上限（`management_by_kind`，形态名 `s_<名字>`）、`short_max_days` |
| 市况开关 | `gate`：`below<n>` 表示等权指数前一日收盘在 EMA n 下方才开新空。“牛市不适合做空”是他们自己的原话，可以作为规则 |
| 指数 | 比对用的同一流动性池（美股 ≥ 5 美元、20 日成交额 ≥ 2000 万，前一天确定）的等权每日再平衡指数；市况开关和“下跌时段”报告共用 |
| 借券 | 数据里没有可借数量和费率，一律假设借得到；引擎字段 `borrow_rate` 默认关闭，空头研究与登记的多空版本用年化 3%，按前一收盘的空单市值每个交易日计提一次，计入该笔盈亏。价格 < 10 美元或 20 日成交额 < 2000 万的空单盈亏单列（现实里常借不到或费率高，偏乐观） |
| 仓位 | 多空共用总仓位、同时持仓上限和账户；`risk_mult` 按原话缩小空单风险 |

每个候选报三个账户：只做多（登记版本）、多空合计、只做空（同一系统去掉多头），加只做空对同池随机做空的安慰剂（同一天、同样止损宽度，种子固定），下跌时段（指数前一日收盘在 50 EMA 下方的交易日，合计与按月），他有日期的空单命中 / 实际做到，头部空单的日 K 供逐笔核对。

**S 轮的选择**（每轮预登记，≤ 5 个候选，跑完不改）：候选必须同时满足

1. 门禁：多空合计的已平仓交易胜率 ≤ 35%（不足 30 笔为未检查）、成交价都在当日区间内；带入前再跑不看未来检查（`shorts gate`）；
2. 多头行为不变：多空合计里的多头已平仓笔数与只做多相差 ≤ 3%、胜率相差 ≤ 1 个百分点、平均持有天数相差 ≤ 10%；
3. 只做空的全段收益高于同池随机做空的中位数；
4. 多空合计相对只做多：全段更高、三个日历年里至少两年更高（改善不能只来自一年）、最大回撤不超过只做多 + 2 个百分点、下跌时段的复合收益更高。

通过的候选里选“下跌时段比只做多多赚的部分”最大的（并列看全段），并且要超过上一轮带入的版本，否则沿用上一轮（第一轮的参照是不做空）。证据不足时回退到更接近原话的版本。胜率超过 35% 的照记、不改门禁，交给用户判断。全部是样本内。

**S 轮门禁 v2（2026-10-19 用户定，替代上面第 3、4 条，之后的轮次都用它；S1–S4 等 v1 轮次的结果不改判）**：空头的任务是“挑出来的有 Alpha、而且不反噬”，不是让空头本身大赚；做空容易被反噬，所以要短、要少。候选必须同时满足

1. 门禁（同上）与多头行为不变（同上）；
2. **Alpha**：只做空的全段收益高于同池随机做空的中位数，且排位 ≥ 0.9；
3. **持有短**：每一笔已平仓空单持有不超过 10 个交易日（候选一律设 `max_days ≤ 10`）；
4. **次数少**：空单已平仓笔数不超过只做多系统已平仓多单的 1/4；
5. **不反噬**：多空合计的最大回撤不超过只做多 + 2 个百分点，下跌时段的复合收益不低于只做多。

通过的候选里选多空合计全段收益最高的（并列看下跌时段增益），并且要高于上一轮带入的 v2 版本。每人 v2 轮次最多 10 轮。
