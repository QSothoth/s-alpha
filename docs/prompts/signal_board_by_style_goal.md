做一个新的“信号看板”（作战单），从流派的角度汇总仓库里所有交易策略今天给出的建议。它和现有的交易员看板（trader-screens）分开：交易员看板回答“每个人今天在做什么”，信号看板回答“按各流派，今天该怎么做、做多大、错了在哪认”。不同流派的建议必须明确分开，不能混成一个名单。

## 为什么要做

现有看板首页是逐人账本加 19 组跨股票共性。共性分组大多是动量流派本来就有的特征（例如“日均振幅 ≥ 4% 有 7 位”），各系统的持仓重合又很低（美股两两重合度多数低于 10%），所以首页信息量低。看板上同时挂着约 70 个模拟持仓，一个人照着做不了。看板也没告诉人：现在适不适合做这个流派、该开多大仓。

## 每个流派一节，内容固定

1. **这个流派靠什么赚钱**：一句话，加上它的收益结构（胜率、盈亏比、持有天数），从回放账户读，标“样本内”。让人知道该期待什么：动量是低胜率、靠少数大赢家；卖 Put 是高胜率、怕单次大亏。
2. **环境档位**：进攻、正常、防守、空仓四档，按该流派自己的条件判断。例如动量看本流派几个系统的市况条件今天有几个放行，再看股票池指数在 20 / 50 EMA 上下；均值回归看它自己的 200 日线条件。档位规则在第 0 步写定，标“未验证”，不按结果调。
3. **主线**（只对动量、成长、趋势）：本流派持仓和今天新开按行业计数，按不同交易员人数排，列前 3 个行业及龙头。
4. **今天的建议**：本流派今天的新开合并去重，最多 5 条，排序规则先写定（例如多人同开优先、冻结版本优先、止损窄优先）。每条写：
   - 股票名、方向、触发价或成交时点（收盘、开盘、盘中）
   - 止损价与止损宽度
   - 按本金和每笔风险算出的股数
   - 出自谁、什么形态
   - 本流派这类形态历史上的胜率和盈亏比
5. **离场提醒**：本流派当前持仓里，今天该卖、或离离场线很近的。
6. **前向记分卡**：冻结日以后本流派各系统的笔数、R 合计和收益，这是首页上唯一不靠回测的证据。

## 首页最上面：跨流派一屏总览

- 每个流派一行：档位、今天几条建议、前向收益。
- 跨流派冲突：同一只票一个流派看多、另一个看空或在卖。只标出来，不合并成一个结论。
- 你的持仓（可选）：读一份手填持仓文件，对上哪个流派哪个系统持有，显示它的离场线；没有对上的标“无覆盖”。

## 约束

- **只汇总，不新增买卖规则。** 所有建议都来自已登记系统和 trend-market-scan 已有的输出，看板不改规则、不加主观过滤；需要的新规则只有排序和档位，第 0 步写定，标“未验证”。
- 不取新数据：只读已有日报 JSON、行业 / 概念缓存和现有面板；缺的标“缺”，不猜、不用占位数据填。
- 多人重合只描述规则行为，不说成胜率更高。全部是“规则此刻会怎么做”，不是投资建议或订单。
- 现有交易员看板的输出字段和 QQ 定时推送不能受影响：新看板放在新的入口和输出目录（建议 `skills/signal-board/`、代码 `studies/signal_board/`、输出 `data/signal-board/out/`）。新建 skill 要同步更新根 `AGENTS.md` 的任务表，`CLAUDE.md` 只写一行 `@AGENTS.md`（测试会查）。
- 运行时只用标准库（研究脚本可用 numpy）；代码英文、文档中文。
- 在单独的 worktree 里做；主目录是生产环境，不提交、不推送，除非我要求。`custody/tests` 和 `studies/trader_screens/tests` 每次都跑；新代码先写单测，至少覆盖去重、排序、档位判定、股数计算和冲突标注。
