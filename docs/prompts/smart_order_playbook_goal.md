## 用户已经定下的事（不要再问、不要推翻）

- **工具是什么**：代替盯盘的原子挂单，只有两个动作。智能买：在用户给定的时间段内买入指定合约和张数；智能卖：在时间段内卖出，只能卖已有持仓（禁止裸卖），止盈止损都算卖。每张单时间段结束时必须成交；一天可以挂多张，互不干扰。时间段在代码里不限制，测试集按用户常用的“到收盘”和“60 分钟”评。
- **适用所有期权**，0DTE 特殊处理（15:45 前必须成交、时间价值衰减快）。
- **选股和方向由用户自己的前置环节决定**，工具不管方向。
- **目标要实际**：分钟级比不上高频，不追求择时收益（期望按 0）。工具要像一位有交易系统、但不做高频的交易员那样不犯错：少买在局部高点、少卖在局部低点，到点一定成交，最坏情况可控。**卖的时候一定要精。**
- **剧本按交易高手的方法论事先写定，不用现有数据拟合**；数据只用来测试。不要回到“为每个 pattern 挑最优策略”的做法（EXEC5 已证明会过拟合）。
- **评测对象是原子单本身（一次成交）**，不要围绕分批设计；TWAP 只作参考线。
- **本机不采集数据**。以后由其他人在其他机器上运行 `studies/us_0dte_picks/exec_capture.py`（每日收盘后抓多档到期的平值 CALL / PUT 1m）。不要安装定时任务。

## 到目前为止的结论（详见 EXEC_RESULTS_CN.md）

- 按期权价格机械择时（等到最后、过半、TWAP、限价）只是在“平均省多少”和“最坏多付多少”之间取舍；0DTE 买单省钱主要靠时间价值衰减。
- 按 pattern 选策略（EXEC5）过拟合；按当天 K 线的单条规则（EXEC4）样本外不比简单规则好。
- 人类规则（EXEC6，开盘缓冲 + 不追急涨 / 不杀急跌）减少坏成交 2–6 个百分点、平均略好；预登记里“最差 5% 不比立即成交差”这条对立即成交恒不成立，是设计错误，后续用“最差 5% ≥ −20%”。
- **移动止损式卖出（从高点回落 X% 就卖）坏成交率最高**，常卖在局部低点，不要再作为卖出默认。
- 场景剧本第一版（EXEC7）：买单减少坏成交但效果 ≈ 简单的“不追急涨”（HB2），最坏情况更大（−24%）；卖单未通过。按场景拆开：**“卖进强势”（急涨后等第一根不再创新高就卖）极好**；所有“等转弱确认再卖”（跌破 EMA9、急跌或深跌后等反弹）在分钟级都太晚，常卖在局部低点。买单里“急跌后等止跌再买”最好，“急涨后等回落再买”最差。

### 2. 执行层改造（剧本二版有结论后再做，或用户要求时）

把 custody 的人工票改成两种原子单：
- 智能买、智能卖；同一合约一天可有多张，彼此独立；卖单只卖持仓，多张卖单之间预留数量防超卖；时间段任意、到点必成交。
- 内置剧本规则与保护；挂价沿用“中间价起步、逐步向对手价靠拢”（`custody/ticket.py`）。
- 每笔订单落库时记录：提交时的买卖报价、成交价、成交时刻、当时的场景，用于以后量挂价效果和在新数据上检验剧本。
- 保留现有安全机制：先落库再发单、客户单号去重、重启对账、只卖实际持有数量、单票和每日权利金上限、交易接口只在 `custody/broker.py`。
