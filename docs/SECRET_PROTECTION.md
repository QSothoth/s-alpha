# 启用密钥提交保护

从仓库根目录执行安装。安装器下载固定版本的 Gitleaks，校验固定 SHA256，再配置本 checkout 的 Git hooks。

```bash
python3 scripts/install_secret_guard.py
```

每个新 clone 都要执行一次。安装器发现已有 hook 配置时会停止，不覆盖其他工具的检查。Gitleaks 是开发检查工具，不是交易程序的运行时依赖。

## 存放凭据

把真实凭据放在仓库外的私有配置目录，通过环境变量加载。限制配置文件的读取权限。仓库里的 `.env.example` 只能包含变量名和占位值。

`.gitignore` 只减少误添加。它不能保护已跟踪文件，也不能阻止强制添加。提交钩子另行检查敏感文件名和实际暂存内容。

## 检查提交和推送

正常使用 `git commit` 和 `git push`。钩子会调用同一套检查器。

- 提交前检查 Git 暂存区，工作树中的未暂存修改不能掩盖暂存密钥。
- 推送前检查待推送的每个提交。先提交密钥再删除，仍然会被拦截。
- 新分支检查全部可达历史。删除远端引用不扫描内容。
- `.env.example` 只豁免文件名限制，仍检查内容。
- 只接受可扫描的文本文件，拒绝二进制及压缩文件，避免扫描器静默跳过内容。
- 工具缺失、版本不符、Git 错误或扫描失败都会阻止操作。
- 诊断只报告规则和位置，不输出密钥原文。

手动检查暂存区或本地全部可达历史：

```bash
python3 scripts/secret_guard.py staged
python3 scripts/secret_guard.py history
```

Gitleaks 默认规则检查常见服务令牌和私钥，项目规则另检查 WxPusher 凭据和富途交易密码字面量。测试和文档不整体豁免。测试中的假密钥应在运行时构造，避免把可用格式的完整凭据留在源码中。

历史中曾提交的少量压缩研究结果和 Parquet 测试文件，在解码检查后按原路径和固定 Git 对象哈希登记在 `scripts/legacy_public_blobs.json`。历史检查只对这些已公开的不可变对象豁免二进制禁令。新增、改名或内容变化不继承豁免，暂存区和发布目录也不使用这份例外清单。

## 处理拦截

先检查报告的文件位置。删除真实凭据，改为读取环境变量，再重新暂存。

如果密钥曾上传远端，先撤销或轮换密钥。删除最新文件或重写历史都不能撤销已经泄露的凭据。

如果只是检测误报，使用最窄的规则调整，并添加测试说明为什么该值不是秘密。不要整体排除文档、测试目录或历史提交，也不要跳过钩子继续推送。

## 检查发布包

`custody check` 验证行情与数据集约束，不承担密钥扫描。发布 custody 数据集时使用安全打包入口：

```bash
python3 -m custody.release --dataset data/custody-0dte-v6 --out data/custody-0dte-v6.zip
```

打包器只接受登记的 CSV 行情及规定的文本元数据，拒绝额外文件及符号链接。它复制允许文件到临时目录，验证副本并扫描内容后生成 ZIP。已有 ZIP 不会被覆盖。不要使用整目录递归打包代替此入口。

如果工作目录有 Parquet 副本，准备一个只含 CSV 和所需元数据的独立发布目录，并更新其中的校验清单。不要删除原始工作目录的数据。Parquet 压缩内容无法由此扫描器可靠检查，因此这个入口拒绝打包。

其他类型的 Release 仍需各自的文件清单。上传前对准备发布的目录运行内容检查：

```bash
python3 scripts/secret_guard.py directory /path/to/release-staging
```

## 远端检查的边界

GitHub Actions 中的 `secret-scan` 检查用于再次发现遗漏。将它设为主分支的必过检查后，未通过检查的提交不能正常合并。CI 运行时内容已上传，不能代替本地钩子或 GitHub Push protection。

本地 hooks 可被 Git 的跳过选项或配置修改绕过。拥有仓库管理权限的人也能修改远端规则。这套保护针对误提交，不是针对掌握写入权限的恶意操作者。

扫描器只能识别配置覆盖的凭据模式，不能识别所有任意字符串密码，也不检查个人邮箱、账户身份或图片中的文字。已有历史身份信息和已发布附件需要单独审计。
