# 交易员看板（trader-screens）

工程为 `/opt/opend-us-options`，沿用根及 `studies/AGENTS.md`。代码在 `studies/trader_screens/`；每位交易员的规则、账户怎么取舍、出处和研究者取值见 [SCREENS_CN](references/SCREENS_CN.md)。

数据层、门禁与横向比对统一按 [TRADER_PROTOCOL_CN](../../docs/TRADER_PROTOCOL_CN.md)：所有交易员用同一份数据集 `trader-data-v1`、同一评测区间和同一引擎，结果先过工程门禁（数据版本、不看未来、成交价在当日区间内、胜率 ≤ 35%），好坏由人对照比对表判断。

看板回答一个问题：如果这些人现在就在这个市场里交易，今天各自会做什么。一个人一天的买点可能有几十上百个，看板不列这些，只列他按自己的仓位规则真会下单的那几笔：每天最多开几笔、同时拿几只、单只多大、先买哪个。

输出是“按这些规则此刻会怎么做”，不是投资建议或订单；按研究约定只做模拟或小资金跟踪。

空单在看板上写成“开空 X 价格，涨破 Y 平空”，持仓表的方向列标“空头”，离场线写成“涨破 X 平空 · 收盘站上某线平空”。平空就是买回股票以结束或减少空头仓位。live 数据遇到除权会把冻结日以前的价格重新复权，回放核对可能出现 1e-9 量级的浮点差，被标成“不一致”，这不是行为变化（冻结数据上回放完全一致）。

研究里改出更好的配置，就在 `systems.py` 登记新版本，看板自动跟着变；冻结要用户同意，前向记录从新版本的冻结日重算。不要在看板里改规则来“让账户好看”。每次运行都把回放截到冻结日，与比对表逐年核对，不一致会在看板上标出。

## 运行

```bash
cd /opt/opend-us-options
PY="nice -n 19 env OPENBLAS_NUM_THREADS=1 PYTHONUTF8=1 /opt/futu-opend/venv/bin/python"
$PY -m studies.trader_screens.scan refresh us                # 把数据补到最新收盘：us / hk / cn（us 另补 Holguin 名单的期权统计，OpenD 按需）
$PY -m studies.trader_screens.scan run us                    # 某个市场今天的看板（终端 + Markdown；会先补数据）
$PY -m studies.trader_screens.scan run hk
$PY -m studies.trader_screens.scan run cn
$PY -m studies.trader_screens.scan board                     # 把三个市场最新一次 run 合成 board.md
$PY -m studies.trader_screens.scan run us --days 5           # 这周的买卖（持仓仍是最新一天）
$PY -m studies.trader_screens.scan industry hk               # 补行业名（OpenD，不扣额度）
$PY -m studies.trader_screens.scan run us --mode frozen      # 只用冻结的研究数据（截至 2026-10-16）
$PY -m studies.trader_screens.scan run us --provisional      # 盘中临时：收盘前约 10 分钟，给出尾盘要买、要卖的单子
$PY -m studies.trader_screens.scan diff us 2026-10-21        # 收盘后：盘中临时结果对照正式结果
```

**盘中模式**（`studies/trader_screens/intraday.py`，报告 [INTRADAY_CN](../../studies/trader_screens/reports/INTRADAY_CN.md)）

2026-10-23 收尾：代码与检查完成；按用户要求停止新增取数和广泛重放。第 5 节只汇总已完成的美股 6 日、港股 8 日选择段，A 股 1 日仅作工程试跑，未做后半验证、未选放大方案。当前使用 V0 原始快照。下面 I1–I3 数字是旧研究记录，不能当作修复后的验证。
- 为什么：多头都在 T 日收盘确认、按收盘价成交、止损在 T 日低点；改成次日开盘买，收益大幅退化（X1 轮）。所以要在收盘前跑、尾盘执行。卖空（开盘或反抽到价位）、跳空止损、盘中止损和按 R 分批在盘中发生，回放里已经成交，不是尾盘要下的单。
- 怎么跑：先在开盘前用 `refresh` 把数据补到上一交易日，收盘前约 10 分钟运行 `run <市场> --provisional`。它只取一次快照，7 个系统共用；把快照当作今天的临时日 K 接在已存数据后面，不写数据，也不进面板缓存。结果单独存成 `out/<市场>_<日期>_provisional_<HHMM>.json` 和 `board_<市场>_<日期>_provisional_<HHMM>.md`，看板顶部标“盘中临时”，展开后列出尾盘单子：收盘价的开多、开空、加仓、平多、平空，平仓包括破跟踪线；当天在开盘或盘中价位已经模拟成交的另列一表。
- 拒绝运行的情况：
  - 非交易日、开盘前、已收盘（半日市按提前收盘算）；
  - 已存数据不是到上一交易日为止（先 `refresh`）；
  - 快照不是今天的（OpenD 的报价时间；新浪只有时刻，要在 15 分钟内，午休除外）；
  - 快照的昨收与我们存的收盘对不上（< 95%）。
- A 股：收盘价在涨停价的买单标“涨停，收盘买不到，跳过”。系统本身不改，名额不顺延。
- 收盘后照常 `run <市场>`，再用 `diff` 分成一致、收盘后消失、尾盘漏掉三类，给出成交价差和止损宽度差。
- 盘中可在不同时间运行；建议开始时点为美股 15:45 ET、港股 15:50 HKT、A 股 14:50 CST，留出计算与操作时间。小样本一致率见报告第 5 节，不按验证结果优化时点。
- 实测合计耗时：美股约 51 秒、港股约 10 秒、A 股约 148 秒（新浪快照占 2 分钟）。建议开始运行的时点：美股 15:45 ET（收盘竞价单的收单截止：NYSE 约 15:50）、港股 15:50、A 股 14:50（不晚于 14:52）。
- 价格、成交量、成交额均用快照原值。修复后的已完成选择段，15:50 美股买入 / 卖出一致率为 88% / 92%，港股为 86% / 89%；无后半验证，不据此选放大配置。完整的假信号、漏信号、分人与分形态计数见报告第 5 节。
- 开盘后 1 小时 / 3 小时跑，只适合当观察名单：美股买入一致只有 31% / 45%，A 股 61% / 84%；早盘看到、收盘不成立的买单尾部风险重。成交量只影响 EP 类信号（Flanders、Marios）。详见 INTRADAY_CN。
- 盘中置信度（I3，`confidence.py`，报告 INTRADAY_CN 第 4 节）：这是一套通用方法，在任意时刻 t 估计每笔盘中单子到收盘还成立的概率 p，分“下单 / 观察”两栏。具体做法是把当天临时 K 线换成几种可能的收盘、重跑 7 个系统，再配一个以时间为输入的全天量模型。
  - **按预登记判定没有启用**：收盘前 10 分钟与直接跑一样；开盘后召回率更高，但精确率比直接跑低。美股 10:30 精确率 69% 对 80%、召回率 69% 对 55%。
  - 模型文件 `reports/confidence_model.json` 记为 `integrate: false`，`run --provisional` 只出直接跑的单子。
  - 原因是阈值在本地子集日上定得太低（0.20），以及“可能触发的止损”被放进了“下单”；要用新数据另做一轮。
  - 早盘想看“离触发还差多少”，只能离线调用 `confidence.live`，当作观察排序，不当下单依据。
- `board` 只合成正式的日看板，不收盘中临时结果。
- 2026-10-23 复核：冷缓存也不写盘；快照完成时刻用于结果文件名和看板时间；拒绝未来报价、采集或回放跨过收盘，少量非当日报价隔离后重新检查覆盖。`diff` 保留同股多次分批 / 跟踪线离场。
- 盘中单子分别列信号价和快照价；A 股正式结果也标记涨停跳过，diff 两边统一排除不可买单。
- 旧 I1/I2 研究曾保留当天真实 `raw_close`，未覆盖股票也曾使用真实收盘，旧一致率只作历史记录。修复后的全股票池复测见报告新增复核节；不把本地子集日算成全名单日，不把已看过的日期称为全新盲测。逐日覆盖可用 `-m studies.trader_screens.minute coverage <市场>` 检查，包含所有名单股票和缺失列表；只读、不取数。
用户已授权的盘中单图定时发布（QQ 频道）：A 股、港股收盘前 15 分钟的尾盘信号，美股开盘后 1 小时的“开盘精选”（只列 5 种收盘情形下都成立的单子，少而精；只做美股）。使用独立的盘中工作树；时间、规则、入口、回执与故障处理见 [盘中发布](references/PRECLOSE_CN.md)。

**数据**（统一接口 `studies/trader_data`，见 [TRADER_PROTOCOL_CN](../../docs/TRADER_PROTOCOL_CN.md) 第 4 节）
- 数据范围（2026-10-29 用户确认）：沿用现有 OpenD、美股 / 港股存量数据及 A 股新浪与存量数据。新增数据源或运行时 mock 配置必须先取得用户同意；不能用占位行情、持仓或信号填充看板。聚合只读取已有日报、分类缓存及现有行情面板，新增展示不需要重新取数。现有卖 Put 权利金与盈亏仍属模型估值，单列并明确说明。
- 看板默认 live：冻结的 Release `trader-data-v1` 加本地增量缓存 `data/trader-live/trader-data-v1/<市场>/`，和复刻研究用同一份底座、同一个面板构建、同一份名单（美股 3433、港股 505、A 股 1697 只）。
- `run` / `refresh` 只补缺的交易日：只缺一个已收盘的交易日时，对整份名单取一次快照（美股、港股 OpenD `get_market_snapshot`，A 股新浪列表），几十秒；缺好几天或今天已开盘时，按名单重读这段历史（美股约 20–30 分钟）。都不扣历史 K 线额度，需要 OpenD 在线（A 股的交易日历也来自 OpenD）。复权比例由交易所的昨收价推出。增量只追加，不改底座。
- 用户要看板即视为同意这次补数；不启动后台或定时采集；不和 trend-market-scan 的取数同时跑（OpenD 订阅上限 300）。
- `--folder` 仍可读其他按 fetch 格式存放的目录（原样读取，不补数）。

**运行与发布**
- 面板按数据摘要缓存在 `data/trader-data/cache/`，数据变了自动重建；之后美股约 10 秒，港股、A 股几秒，单进程即可。
- 结果写 `data/trader-screens/out/`：`<市场>_<日期>_<天数>d.json` 和单市场的 `board_<市场>_<日期>_<天数>d.md`。
- `board` 把三个市场最新一次的日看板合成 `data/trader-screens/out/board.md`（每次覆盖），并另存 `board_<日期>.md` 留档。收盘后依次 `run us` / `run hk` / `run cn`（会先补数据）→ `board`。仅调整展示时直接读取现有 JSON 重排，不运行补数。
- 本机图片入口 `research/trader_board_cards.py` 的 `build_post` 同时输出图片、`board.html` 和 `board.md`；HTML 是现有数据的本地浏览文件，支持市场 / 股票 / 交易员查找、逐股展开和个人账本折叠，不使用 Sites、不增加托管或取数服务。图片首图是共识与分歧，后续按股票列完整价格与离场线；不再逐位摊开交易员卡片。

## 怎样读看板

**每个市场一节**
- 一句市况：股票池等权指数在 20 / 50 EMA 上方还是下方。
- **跨股票共性**：行业、概念、入场形态、量能、价格位置、相对强弱、波动、流动性、仓位与止损距离；至少两位不同交易员、两只股票，阶段与多空分别统计。首页每类选代表组，完整成员、数值、覆盖率和规则可展开；与美股开盘后 1 小时单图共用。盘中量能只用原始累计量，不用情形推演量，旧快照缺量不补猜。具体门槛与分母见[聚合口径](references/AGGREGATION_CN.md)。
- **共识与分歧**：一只股票一行，并排显示当前持仓、新开 / 加仓、退出 / 减仓及对应交易员。共同持有按当前持仓计算；多人新开必须是不同交易员在同一天同方向开仓，加仓和涨停跳过不算。共同退出要求至少两位不同交易员在同一天平掉或减少同方向仓位，平多与平空分开，多次分批只计一人。新开加入老持仓要求另一位交易员当前仍持有、且开仓日早于这笔新开；退出与持有并存也要求是不同交易员。当前多空持仓和同日多空新开分别标注。
- **动作**：统一写“开多 / 加多 / 平多 / 开空 / 加空 / 平空”，部分平仓明确标“部分”。平空是买回股票、结束或减少空头仓位（回补），不当作开多。新开后已不持有会标明；当前持仓包含本期新开后仍在持有的仓位，不重复计算人数。看多天时保留动作日期，不能把不同日期的入场说成同日共识。卖 Put 单列，不混入股票多空统计。
- **折叠内容**：其他信号与持仓、卖 Put、账户概览、各人的完整账本。账户保留版本、流派、仓位、市况、账户收益与回撤、冻结后收益。各人明细保留形态、成交价格、开仓日、盈亏、仓位、未执行信号及**下一交易日的离场线**；离场线仍从引擎持仓状态读取，不在展示层推算或覆盖。盘中成交标注（开盘）（盘中），当天无报价的持仓标注估值日。
- 这些关系由 `focus.stock_groups` 对已有记录确定性计算，Markdown、HTML、日报图片和盘中图片共用；多人重合只描述规则行为，不据此推断更高胜率。

**末尾**：回放核对一句（只有每个系统都有同配置、同代码的比对表参考且分年收益一致时才写“全部一致”；没有参考的列出“未核对”，不一致的会在对应市场里标出），以及折叠的各系统规则（选股与形态｜入场与止损｜离场｜仓位与市况）。

**执行时点**：多头买入和跟踪线离场是收盘价，“今天买入 / 卖出”大多是收盘那一刻的操作；卖空和止损类在盘中，看板标了时点；收盘后才看到时实际只能次日处理，而次日开盘买会让收益大幅退化（X1 轮）。要按系统执行，用盘中模式（`run --provisional`）在收盘前拿到单子、尾盘下单。
