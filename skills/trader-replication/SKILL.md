# 逼近一个交易员（trader-replication）

工程为 `/opt/opend-us-options`，沿用根及 `studies/AGENTS.md` 的研究规范（预登记、每轮 ≤ 5 个候选、选择段与验证段分开、失败照记、不为单个 case 拟合）。方法、口径与常见坑见 [METHOD_CN](references/METHOD_CN.md)；做过的例子各有一份参考：[Martin Luk](references/MARTIN_LUK_CN.md)（第一个例子，含运行命令）、[Sean Ryan](references/SEAN_RYAN_CN.md)（第二波，逐轮按时间切分、验证段未通过）。

数据层、门禁与横向比对统一按 [TRADER_PROTOCOL_CN](../../docs/TRADER_PROTOCOL_CN.md)：所有交易员用同一份数据集 `trader-data-v1`、同一评测区间和同一引擎，结果先过工程门禁（数据版本、不看未来、成交价在当日区间内、胜率 ≤ 35%），好坏由人对照比对表判断。

立场按根 [AGENTS.md](../../AGENTS.md)“挖掘与复刻策略的立场”：他公开做到的结果先当作能做到，一次失败只否定我们的那个版本；前期为什么会一再误判“他不行”，见 METHOD_CN 第 0 节。

继续既有系统或更换主目标前，必读 [R75–R108 方向错误复盘](../../studies/martin_luk/reports/POSTMORTEM_R75_R108_CN.md)及 METHOD_CN 第 9 节的方向审查要求。不能用缩短持有期抵消未获授权的年度收益退步，也不能在上游可达上限低于目标时持续优化下游；“按预登记通过”不自动等于可以替换用户的基线。

本 skill 管研究过程；按各交易员思路的每日 / 每周筛选、冻结系统的规则账户和前向记录在 [trader-screens](../trader-screens/SKILL.md)。结论都是区间内的研究结论，不是投资建议；本 skill 不碰交易接口。

## 复刻成功标准

2026-10-29 用户定。下面 7 条全过才算复刻成功，逐条由 `studies/trader_replication/success.py` 的 `judge` 判断（缺数据的条目一律判不过）。我们只要高盈亏比的系统，胜率高没有意义。

| # | 规则 | 说明 |
|---|---|---|
| 1 | 门禁全过：数据版本与区间、不看未来、成交价在当日最低—最高之间、**已平仓胜率 ≤ 35%**（≥ 30 笔） | 所有风格都适用，没有例外；前三项由 `gate.py` 在 `compare run` 时检查 |
| 2 | **每年 ≥ 52 笔**（至少一周 1 笔），且在他本人宣称笔数的 ±30% 内或宣称的区间内 | 数字要有原文出处、核过年份与口径；没有出处一律不过（METHOD 第 9 节） |
| 3 | 他公开过的其他行为（胜率、平均赚 / 亏、持有天数）各在 ±30% 内 | 他没公开的不要求 |
| 4 | 他在数据期内有成绩的年份，收益与我们的差 \|log((1 + 我们) / (1 + 他))\| ≤ 0.3 | 成绩在数据期外的不要求 |
| 5 | 全段跑赢同池随机入场中位数 | |
| 6 | 验证段（没参与调参的时段，只评一次）跑赢同池随机入场中位数 | 不要求为正 |
| 7 | 去掉收益最大的两笔交易后重跑（`success.drop_top`），全段仍跑赢同池随机入场中位数 | 低胜率本来就集中，这条只排除全靠一两笔 |

回撤、盈亏比、港股和 A 股的结果、参数邻近值只报告，不作成功标准。

研究过程中的要求（不是成功标准，但要照做）：

- 准入：本人一手规则；≥ 30 笔带日期的公开交易台账（第 0 步）。没有台账或笔数没有出处的，只能叫“按他原话的规则评测”，不进入第二阶段逼近收益。
- 每轮：预登记、≤ 5 个候选、跑完不改；不带入比参照更差的配置；有台账的，命中与实际买到他的票不低于参照。门槛在第一轮预登记里写定，研究中途不临时加或去，要改须另写预登记（用户决定的照记）。
- 收益像、行为（笔数、持有期、实际买到）不像的，标成“另一种策略”，不算复刻。
- 冻结前：三个市场都报（只在他的市场调参）、按年、等权持有、稳健性（`robust`，只报告），用户同意。

## 步骤

0. **选人与准入**：从 [35 人档案与风格注册表](../../studies/trader_registry/README.md) 读个人档案、来源账本与缺失规则，按三条分级：有没有本人一手规则、能不能建 30 笔以上带日期的公开交易台账、他交易的市场和周期我们有没有数据。A 可做；B 先补资料（台账不够）；C 暂缓（只有身份或成绩、框架未核实，或依赖拿不到的数据，如历史流通股本、借券、竞价逐笔、私有模型），写清缺什么，不造实现。暂缓的理由只能是资料或数据，不能是“这种风格不可能有效”。注册表只是导航：历史分支里的实现不代表 main 已有，那些实验没有台账、没量保真度，否定结论要按本流程重测；未知字段不用相似交易员代填。
1. **找资料、按环节摘原话**：长访谈的逐笔复盘、本人直播 / 复盘视频（只下字幕：`yt-dlp -6 --skip-download --write-auto-subs --sub-langs en-orig`，视频间隔 60 秒以上，遇到 HTTP 429 退避 20 分钟）、帖子。原话按环节整理成 `studies/<交易员>/notes/RULES_CN.md`，每条带出处（视频 id + 时间戳或链接）。二手摘要只当线索；书和付费课程只做摘要和短引文，不入库全文。
2. **建交易台账** `studies/<交易员>/notes/trades.csv`（格式与校验见 `studies/trader_replication/ledger.py`）：至少 30 笔，标日期精度（exact / chart / window），能用成交价、事件日核对的都核对；直播里“今天 / 昨天 / 周四买的”换算成交易日。台账冻结、提交后再跑检验；按时间切选择段 / 验证段，切分点写进第一轮预登记。
3. **准备按当时条件的数据**：全市场日 K（含后来冷掉的股票），名单只用 t−1 及以前的数据；分钟线只在按当时条件随机抽样的子集上比较入场。历史 K 线额度至少给 custody 留 80，扣新额度先问用户；一晚最多新拉 150 只；磁盘保持 5GB 以上。
4. **端到端粗版本、三层对照与基线漏斗**：trader-screens 里已有这个人的按原话初版的，从它开始；环节按他自己的流程拆（不同风格的拆法见 METHOD_CN 第 5 节，不要硬套上一个人的环节）；先按他的原话把每个环节都搭上（粗糙也行），组成完整版本；再做三层对照（他的票 + 他的执行、他的票 + 我们的执行、我们的票 + 我们的执行，见 METHOD_CN 第 0 节），定位差距在执行还是选股；然后看他的选择段交易每笔丢在哪一环。
5. **逐环节优化**：每环一轮或多轮（默认每环最多 20 轮，提示词可另给预算），候选来自他的原话或逐笔诊断；选择段按“宽度上限内命中率最高、超额不为负”选，验证段只评一次；“更像他”和“有超额”分开记。某环怎么都过不了就记进否定登记表（当时其余环节的配置、依据），进入下一环；下游大改后把依赖旧配置的否定重测一次。上一个交易员学到的东西只提示“去哪儿查”，不搬参数。
6. **完整系统**：组合各环节选择，美股、港股、A 股都跑（只在他交易的市场上调参，其余市场只量超额），和同一名单随机入场的安慰剂、等权持有比较，按年拆开；另报验证段命中他交易的比例；与他公开的统计对照。
7. **逼近他的收益**（第二阶段，见 METHOD_CN 第 9 节）：在完整系统上逐轮只改一处（互相牵连的环节成对改），按预登记的目标带入，要求跑赢同池安慰剂、命中不降，绝不带入更差的配置；每几轮做一次逐笔诊断（他的每笔交易卡在哪一步），“命中”和“实际买到”一起报，行为约束（实际买到、笔数、持有期）当门槛，防止优化出另一种赚钱方式；具体数字按上面“复刻成功标准”第 2、3 条；进入本阶段前先有台账、笔数有出处。候选仍须来自他的原话或诊断，不做网格搜索。
8. **写结论**：逼近到什么程度、还差在哪。每个差距都落到具体一层（缺数据、执行方式、规则本身没有超额、像他和赚钱背离），并写明是在什么配置下得出的；“无法机械化”只有在三层对照显示他的票交给我们的执行也做不到时才能写。
9. **冻结与交接**：用户认可某个配置后冻结：报告文件和冻结日（数据最后一天）在 `studies/trader_screens/frozen.py` 加适配类，之后由 trader-screens 每日扫描并记录冻结后的表现。冻结后的表现是这个系统唯一的样本外；之后再改配置属于研究，要重新冻结，前向记录从新的冻结日重算。

## 新交易员的目录

新建 `studies/<名字>/`：`notes/RULES_CN.md`、`notes/trades.csv`、`notes/PREREG_R*.md`、`notes/rounds/`，再写一个像 `studies/martin_luk/replicate.py` 的环节模块（各环节的掩码函数和各轮入口）；台账、命中率与漏斗、同日同波动组超额、多空组合与安慰剂直接用 `studies/trader_replication/` 的 `ledger`、`fidelity`、`edge`、`system`。新环节规则先写执行时点单测；分钟线入场只用触发前可知的条件。做完写 `references/<名字>_CN.md`（做了什么、学到什么、怎么运行），并更新注册表里这个人的实现状态和路径。

一次只跑一个重计算进程（两核机器满载会被外部停机），用 `nice` 和 `OPENBLAS_NUM_THREADS=1`。
