# 逼近一个交易员：方法与口径

适用于任何公开过做法和交易的主观交易员。第一个例子是 Martin Luk（`studies/martin_luk/`），通用代码在 `studies/trader_replication/`。

## 0. 立场：先相信能做到，再找差距在哪

规则写在根 [AGENTS.md](../../../AGENTS.md)“挖掘与复刻策略的立场”。这里记下 Martin Luk 例子里为什么会一再得出“他的策略不行”，以及两件要照做的事。

### 前期一再否定的原因（2026-10-18 复查）

| 错在哪 | 例子里的表现 | 后来证明 |
|---|---|---|
| 用挖新 Alpha 的立场做复刻：默认没有，证据不足就判否 | R8、R9、R12 都以“差距只能来自公开描述之外的判断”收尾 | 第二阶段按他的原话逐环补齐后，美股 2024 年 +288%（他 +283%） |
| 没量保真度就下结论 | R11–R18 的流程只命中他 42 笔有日期买入中的 2 笔（R19），被否定的是我们的翻译 | 建台账后名单能装下他七成以上的买入 |
| 尺子对凸性策略不利 | R9 判“入选股只是波动大、没有方向优势”（10 天内涨超 20% 的概率 30% 对 13%，跌超 20% 的概率 29% 对 9%），可他止损只有 2%–3%，波动大正是他要的；R25 EMA21 跟踪排安慰剂 96 分位，因每笔 R 区间含 0 被否 | R31 只把离场换成 EMA21，2024 年从 −3.4% 变成 +56.9% |
| 环节脱离上下文单测 | “止损宽于 min(5%, ½ADR) 就不做”跳过了他 2024 年 13 笔多头里的 12 笔（R29）；R8、R10、R12 把他的规则用在随机领涨股上 | 改成止损放到上限照做、下限 1%（R30、R44）后才打开 |
| 低功效 + 不通过就沿用参照 | 每环退回最初的粗糙版本，组合后 2024 年 −24% | 第二阶段改为按目标带入，系统才动得了 |
| 只审查好结果 | 事后热门池、盘中未来函数、极窄止损都查出来了，坏结果却没查实现 | R29 拿台账逐笔追，才查出跳过宽止损的问题 |

第二阶段又走到另一头：以收益为目标、行为约束只看信号面命中（每天 36–239 个信号，面宽自然命中高），优化出“每天买成交额最大的 4 只动量股”，实际买到他的票只有 5/42、0/40。R52 “按更像他的方式排序就亏”也还不能下结论：只改了排序，其余配置是围绕大成交额股票调出来的，他对小盘高波动股的仓位和离场不同（单只 20% 以下、3R / 5R 分批、跌破 9 EMA 就走）。

### 三层对照回放

有真实交易台账就做，放在基线漏斗之前，每个阶段结束时再做一次：

| 层 | 票和日子 | 执行（入场、止损、离场、仓位） | 回答什么 |
|---|---|---|---|
| ① | 他的 | 他的 | 他的真实成绩（台账里的结果 / R，公开统计） |
| ② | 他的 | 我们的 | 他的票交给我们的执行能赚多少 |
| ③ | 我们的 | 我们的 | 系统本身 |

① 与 ② 的差是执行差距（盘中入场、止损位置、离场节奏），② 与 ③ 的差是选股差距。只有 ② 明显不如 ① 时，才能写“他的优势在盘中执行”。② 用 `trader_replication.system.simulate`，把入场元组换成台账里他的票和日子（当天收盘买入、按我们的止损规则）；目前没有现成入口，要在各交易员的环节模块里写。股票在本地有分钟数据的，再用分钟线做一版盘中入场。

### 否定登记表

每个“不通过”记一行：哪一轮、否定了什么、当时其余环节用的是什么配置、否定依据（哪项门槛、效应量和区间）。下游环节大改后（离场、仓位、股票池换了），把表里依赖旧配置的否定在新配置上重测一次，再决定是否维持。Martin Luk 例子里还没重测的有：5 分钟入场（R24、R24b，在旧离场、200% 仓位、跳过宽止损下否定）、止损（R16）、R52 的更像他的排序。

## 1. 三把主尺子

| 主尺子 | 回答什么 | 主数字 |
|---|---|---|
| S 信号覆盖 | 每晚几只时，能否及早点到他的段 | 留出段 K=3 早期覆盖，连同同冷却不限 K 的平均新名数报告，见 §11.2 |
| 交易行为 | 实际买到没有，买卖节奏像不像 | 实际买到、已平仓胜率、盈亏比、持有天数、每年笔数，见 G4 |
| 账户 | 每年是否不亏，离本人公开成绩多远 | 分年收益及财富比的对数距离，见 G5 |

`C_signal`、`net_share`、`forward`、`precision`、`C_trig`、`P_opp`、`E` 都是诊断列。`fidelity` 的同宽随机基线、`edge` 的10天超额、账户的随机入场与去两笔结果也只作诊断，不作否决。它们不能替代三把主尺子；旧报告不回改。

只出现信号不等于买到，买到不等于拿住。三层对照仍用于定位差距，不再另立一张成功标准表。

## 2. 台账（trades.csv）

一行一笔公开交易，格式见 `studies/trader_replication/ledger.py`：`id, ticker, side, entry_date, window_lo, window_hi, precision, setup, trigger, stop_pct, outcome, r_multiple, source, note`。

- `precision`：`exact`（他自己说的日期、只在一天出现过的成交价、选举 / 财报这类事件日、直播当天）、`chart`（按他对图形的描述在日 K 上对出来的，窗口留出不确定的天数）、`window`（只知道一段时间）。
- `chart` 交易是按他的描述对日期的，用它检验“形态那天有没有出信号”有循环论证的成分：报告时把 `exact` 单独列出。
- `source` 写到视频 id 加时间戳（或帖子链接），能回查原话。
- ETF、期间退市股不在股票面板里，记下但不计入命中率分母。

## 3. 资料从哪来

1. 长访谈的逐笔复盘（TraderLion 这类节目）：用 `yt-dlp --write-auto-subs --skip-download` 只取字幕，信息密度最高。
2. 本人直播 / 复盘视频：日期就是直播日，最适合做验证段。字幕要取 `en-orig`（原声识别）；有 AI 配音的视频，`en` 是配音轨的回译，股票代码会被译乱。YouTube 会对字幕接口限流（HTTP 429），每个视频间隔 60 秒以上、遇到 429 退避 20 分钟。
3. 二手摘要只用来找线索，不进台账。
4. 日期用价格核对：他说的成交价、止损价、事件日在日 K 上能唯一对上的记 `exact`。

## 4. 分段与预登记

- 台账按时间切两段：选择段用来挑方案，验证段每轮只评一次；切分点写进第一轮预登记，之后不改。
- 行情区间另按研究惯例切（例：2024 年选择、2025-01 → 2026-10 验证）。
- 每轮 ≤ 5 个候选，先写预登记（来由引他的原话、候选、选择规则、通过条件），跑完不改；失败照记。卡子未通过时主改该层；信号与仓位可paired成对改，选择仍只用上游覆盖，不能用账户收益替代。每个候选写清新机制、可达上限与独立尝试数，无新机制不得续轮；失败记进否定登记表，下游大改后复测依赖旧配置的否定。
- 选择规则先满足 G3 的 S 覆盖与宽度，再比较预登记主目标；随机基线和10天超额不作否决。证据不足、候选与参照分不开时，回退项设为更接近他原话的版本，不默认退回最初的参照。

## 5. 环节

按他自己的流程拆，每环都在上一环选中的结果之上比较。下表是动量波段（Martin Luk 这类）的拆法；其他风格见表后的“按风格调整”，不要把上一个人的环节硬套到下一个人身上：

| 环节 | 问的问题 | 典型候选 |
|---|---|---|
| ① 股票池 | 他从多大的池子里挑 | 价格、成交额、ADR 门槛 |
| ② 什么算强 | 他的扫描 | 1/3/6 月涨幅排名、绝对涨幅、前一日最强、多张榜 |
| ③ 观察名单 | 进名单后怎么分层、留多久 | 均线结构、周线、升级、题材 |
| ④ 形态 | 他买入当天的样子 | 越过前高、内包 / 窄幅、跳空、回踩均线 |
| ⑤ 入场 | 盘中何时、什么价 | 收盘确认、次日开盘、分钟线触发（只能在有分钟数据的无偏子集上测） |
| ⑥ 止损和离场 | 止损宽度、分批、跟踪 | 当日低点、均线跟踪、没有延续就走 |
| ⑦ 仓位与市况 | 每笔风险、总仓位、何时收缩 | 固定风险、反馈降风险、指数 / 名单宽度过滤 |
| ⑧ 空头 | 他的空头形态 | 反抽均线、跌破前低、市况过滤 |

### 按风格调整

风格标签取自注册表，细节以个人档案和来源账本为准。

| 风格 | 注册表里的例子 | 环节怎么拆 | 数据与常见缺口 |
|---|---|---|---|
| 动量波段：强势股、紧止损、均线跟踪 | Martin Luk、Qullamaggie、Christian Flanders、Clement Ang、Oliver Kell | 上表 8 环 | 日 K 能做大部分；他的盘中入场只能在有分钟线的子集上测 |
| 成长股趋势 / 长持：相对强度、VCP、底部突破、集中持有 | Mark Minervini、Ryan Pierpont、Vibha Jha | 股票池 → 基本面与相对强度 → 底部 / 收缩结构 → 突破买点 → 加码 → 周线或长均线离场 → 集中度 | 基本面要按当时可知（公告日之后）；持有期长，交易笔数少，台账要跨更多年 |
| A 股产业预期 / 主线反复 | 二池、投资如人生（左侧潜伏） | 产业或事件预期 → 主线识别（同板块同涨、成交集中）→ 龙头 / 中军 → 回踩或左侧买点 → 涨跌停、T+1 约束 → 主线退潮或均线离场 | 板块、概念标签多是事后整理，会引入未来信息；涨停收盘买不到 |
| ETF 波段 / 超跌反转 | 张棋、叙市 | 标的池 → 超跌或价格位置 → 反转确认 → 持有到修复 | 专有指标公式缺失时只能按描述近似，要标明是近似 |
| 日内、竞价、做空 | Goverdhan Gajjala、Ty Rajnus、这股有毒 | 盘前名单 → 分钟线或竞价触发 → 当日离场 | 要分钟线、历史流通股本、借券、竞价数据；先查能不能拿到，拿不到就暂缓（准入 C） |

最后把各环节的选择组合成完整系统，三个市场都跑，写清楚：每环命中率、完整系统命中率、交易统计与他的对照、相对安慰剂的位置、差在哪。

## 6. 股票池必须按当时条件

- 全市场日 K（含后来冷掉的股票），每天只用当时可知的价格、成交额、排名；名单在第 t 天只用 t−1 收盘及以前的数据。
- 分钟线如果只有事后挑出的热门股，只能做诊断；要比较入场方式，用按当时条件随机抽样的子集。

## 7. 常见坑

- 事后热门名单：随机入场也赚钱，判断超额只能看同名单安慰剂。
- 日 K 看不到盘中先后：触发价入场 + 当日低点止损在日 K 上无法判断是否先止损，要么收盘确认，要么用分钟线子集。
- **盘中入场的未来函数**：日线形态里用到当天最高 / 最低 / 收盘的条件（比如“回落后收回”）只能用于收盘确认入场；做分钟线触发时只能用开盘前可知的条件，回落和突破交给分钟线本身（`replicate.pre_open_masks`）。Martin Luk 例子里这个错误让验证段从 −25% 变成了 +56%。
- **随机基线**：名单收窄后，随机命中只能在该股票当天在名单里的日子发生（`fidelity.recall` 的 `pool`），否则提升倍数会被压到 1 以下。2026-11-05 起选股覆盖不再拿“同池随机挑票”作对照（用户：随机挑没有意义）；随机挑都能对上不少，说明尺子太松，应改尺子（第 11 节）。P1 起收益层随机入场与去两笔也只作诊断；旧轮次的判定不回改。
- **宽度上限**：按他的工作量定（扫描池几百只、名单几十只、每天信号十几只），定得太窄会让所有候选都不可选；改上限要另开一轮预登记，不回改本轮。
- 他说的门槛要逐条量，不要默认有用：例子里“只把 1 亿美元以上的加进名单”让名单内超额变负。
- 极窄止损（< 0.5%）让 R 失真：报告止损宽度分布。
- 机器两核：重计算单进程 + `nice`，不并行；4GB 内存，全市场面板按 float32 存、按需转换。

## 8. 结论怎么写

- 每个阶段按第10节的四行报告。主成绩是 S、交易行为与账户；超额列作诊断，失败照写。
- 完整系统：三个市场的收益、回撤、按年、笔数、胜率、平均赚 / 亏、每笔 R 区间、等权持有、安慰剂位置；美股另报验证段命中他的交易。
- 与他公开的统计逐项对照（胜率、赚亏、频率、持有天数、收益），写清“逼近到什么程度”和“差在哪”：哪些是数据缺口、哪些是规则本身没有超额、哪些是他的盘中判断无法机械化。

## 9. 交易与账户：保留基线，先定位再改

第一阶段每个环节都按“像不像”和“有没有超额”选，组合起来的系统在他拿冠军的 2024 年反而亏损。第二阶段改为直接逼近他的收益，下面这些是 Martin Luk 例子里摸索出来的做法。

- **带入规则**：每轮在有效主线配置上只改一处，互相牵连的机制可成对改；候选须守住 G3、G4、G5 和用户要求的实际成交约束；随机入场结果及稳健性只报告。比较必须同时保留用户原始基线、有效主线和本人目标，不能只比最近一个较差版本。行为主目标不自动授权年度收益退步；未获授权的权衡版本只作诊断，不替换主线。收益目标按用户规定的距离衡量，不把更高收益机械等同更像本人。旧 `replicate.minyear_round` 只有其历史轮次的选择逻辑，不自动保证上述完整约束；运行前须核对实际选择器。
- **笔数必须对上本人宣称的**（2026-10-26 用户要求）：每年笔数是硬门槛，不只是加分项；对不上就不算复刻，收益再像也只是另一种策略。目标数字要回原文核对年份、账户、口径（平均还是上限），在 `RULES_CN.md` 写明原话；只有区间时按区间写（`goal_behaviour = dict(per_year=(lo, hi))`）。本人没公开笔数的，只报告“无法核对”，不代填目标；每年至少52笔仍是硬线。旧 `goal.meets` 保留历史选择语义，不是 P1 的成功判定。反例：Sam 的“约 400 笔”是 2019 年的数字，被当成 2024 年目标用了 12 轮；“平均每天 5 笔以下”被实现成每天上限 5 笔。
- **目标会把系统带偏，改目标要记录**：只追冠军那一年（R31–R34）会把另一年做坏（L2：2024 +161%、2025 −29%）；按“三年里最差一年”（R35–R39）又会被只有 9 个月的当年卡住；最后定为“两个冠军年里较差的一年，当年为正”（R40 起）。每次改目标都写进预登记，并注明是看过哪些结果后改的。整段行情从此是样本内，结论属于同段择优。
- **轮次写成数据**：候选写在 `notes/rounds/R*.json`（基础配置 + 每个候选改哪几项），`replicate.py round R42` 运行，结果在 `reports/r42.json`。这样每轮的改动一目了然，跑完不能改。
- **逐笔诊断**：对他每笔有日期的交易，看系统最远走到哪一步——没信号、被市况挡、被每天笔数上限挤掉、没有仓位空间、买到（`replicate.py diagnose`）。下一轮改哪一环由这张表决定，不靠猜。
- **“命中”要和“买到”一起报**：信号面很宽时（例子里每天 36–239 个入场），命中率主要来自面宽，真正的选择发生在排序和每天的笔数上限。从 R51 起每轮另报“系统实际买到他的票”的笔数。
- **像他和赚钱可能是两回事**：例子里把排序改成更像他（按当天涨幅、题材扎堆、放量），买到的他的票更多，收益却从 +335% 变成 −74%；能赚钱的版本买的是成交额最大的动量股。遇到这种情况要如实写出，不要把赚钱的版本说成复刻。
- **机制问题先查**：多空共用总仓位时，空单排在多单前面会把多单挤掉；止损太宽时“跳过”会正好跳过他的大日子（改为把止损放到上限照做，并设止损下限 1%）；收盘信号里的盘中条件不能拿去做盘中触发。
- **引擎能表达他的规则**：分批（按 R / 按信号）、跟踪线在分批后切换、保本、高位放量全卖、加码、新仓反馈调风险、按日风险倍数、同时持仓上限，都在 `studies/trader_replication/system.py` 的 `Rules` 里，默认关闭；新规则先写执行时点单测。
- **两两组合**：只改一处的逐轮搜索会卡在“一年好一年坏”（某个改动让 2024 年大涨、2025 年变差，另一个相反）。把偏一年的改动两两组合单开一轮（例子里的 R60、R69），预登记里写明是看过各自结果后挑的。
- **最终配置必须做稳健性**（`replicate.py robust`，只报告、不用来选）：邻近参数各挪一步、逐项关掉加码 / 风险倍数等规则、成本加倍、起始日期往后挪。例子里邻近参数方向不变，但每天笔数差一笔、全区间差几倍；起始日期晚两三个月，2024 年就从 +288% 变成 +6%～+25%。这些都要写进结论，不能只报最好的那条路径。

2026-10-18 的 [R75–R108 复盘](../../../studies/martin_luk/reports/POSTMORTEM_R75_R108_CN.md)记录了另一种失败：先以缩短赢家持有为由把 R74 的 2025 +221.19% 换成 R81 的 −11.20%，再用 R81 的局部行为优势限制后续选择；上游资格与触发的覆盖上限低于目标，却长期调名额、重入和排序。防复发不能只加一个收益门槛，还必须改变决定研究方向的方法：

1. **先验算能否到达，再选调整层。** 每阶段先算数据覆盖、资格、触发、市况的完整窗口上限与交集。若保留的上游条件已经使目标不可达，下游排序、名额、仓位和退出只能做局部诊断，主要实验必须改变造成上限的层。缺数据不能擅自扣新额度，也不能从分母中悄悄删除。
2. **把拒绝日志当线索，不直接当根因。** “被每日名额挡住”也可能源于更早的低质量机会；“仍持同票”可能源于入场、退出或重复尝试定义。候选须说明影响哪一层、多少独立尝试、什么机制。必要时用小范围配对诊断区分解释，再做完整账户；不为单笔加例外。
3. **核对规则的主体、时点、分母和类型。** 新增股票不是给旧票加倍，盘前/同时段放量不是累计量超过全天均量，短持均值不是所有趋势单必须快退。先验证整份台账上的机制和普通候选误触发，再研究精确公式；近似失败后应回到这些含义，不能只换参数。
4. **固定主线，允许独立探索。** 未通过采用门槛的分支可继续检验新机制，但不得自动升级，也不能用它的局部最优统计锁死原基线。发现主线选错时回到用户有效基线并记录原因；旧轮次结果不改。预登记限制的是事后改写结论，不要求继续执行已发现偏离任务的选择规则。
5. **检查点必须做方向审查。** 对照原基线报告整体差距是否缩小；若没有，写明哪项核心假设仍未改变、什么新证据支持下一组实验。已知上限不足立即转向限制层；没有新机制依据，不因轮次无限就重复同类搜索。转向不等于擅自停止用户要求持续进行的任务。
6. **成果与过程分开报。** 先报有无可替换用户基线的方案，再报机制发现、数据修正和代码验证。不得以“赢随机”“单轮通过”“只差一个内部门槛”或测试数量，替代整体目标上的进展。

P1 的 `pipeline.allowed_actions` 与新 round 校验只约束显式提供的卡子结果和配置层。它们没有证明所有旧研究脚本都遵守这些流程，也不授权重启已叫停的研究。

### 11.3 账户成交、资金与利润的精确口径

只用真实 fill。每个买入 lot 按成交日归到 `[first−3, peak)` 内的同票段；重叠时取成交价至 top 剩余涨幅最大的段，平手取更早 first，每 lot 只归一段。FIFO 匹配减仓，购买/出售费按实际名义分配；与台账 pnl 的残差必须公开、按买入名义分配并核对。

按段报 `any`、早买、`synced`、offset、首笔 fill。早买用该段实际首笔 lot 的买价与**首锚点 gain**比较，后来加仓/再试不重置首笔时钟；至少剩一半算早买。`synced` 为在其任一公开锚点前 3 天到后 2 天成交，只报告。first−3 买、first−1 已卖可以算早买诊断，但没有跨过本人入场日，资金和利润不归 H。

T1/H 是归到大段且至少持有至本人入场日的 lot；只计到 `min(lot_exit, peak, exit_known)`，持有超过峰值按峰值日**收盘**切开，峰后盈亏进 `post_peak`。不用最高价虚构卖出。T2 是其他公开多头小段的相同窗口内部分；T3 是他当年公开做过的股票但段外的交易；其他股票归 other。T1+T2+T3+other+post_peak 与交易 pnl 对平，O=总 pnl−H。T2、T3、峰后收益不能冒充 H。

设 lot 名义为 `q_l p_l`，首锚点总涨幅为 `γ_g`，窗口内含分摊费用的盈亏为 `π_l`：

```text
capture_total = Σ(T1 π_l) / Σ(T1 q_l p_l γ_g)
capture_rem   = Σ(T1 π_l) / Σ(T1 q_l p_l (top_g/p_l−1))
GP_H          = Σ(T1 max(π_l, 0))
GP_all        = Σ(同一 FIFO/时间切片口径 max(π_l, 0))
purity_gross  = GP_H / GP_all                 # GP_all=0 时 None
H             = Σ(T1 π_l)
O             = 总交易 pnl − H
purity_net    = H / 总交易 pnl                # 总交易 pnl≤0 时 None
tuition_loss  = Σ(非 T1 min(π_l, 0))
```

capture 按 lot 资金潜力加权，不能平均每段比例，也不能用首笔名义承接全部加仓盈利。买价低于本人锚点时 capture_total 可能 >1；低位反复交易时 capture_rem 也可能 >1，照报。没有交易的段无 capture 分母，未参与的损失由早买段覆盖另量。O>0 是其他业务的净贡献，不能叫净学费。

每日以收盘持有股数计算 `X_t=Σ q_l,t close_l,t`，`X^H_t` 仅计 T1 且截至 peak；实际卖出日收盘无持仓，期末 end 估值仍保留当日敞口。确认仓仅从真实 confirmed_day 起计算，不能追溯计入确认前的试仓。`E_t` 为账户收盘权益：

```text
cap_equity = mean_t(X^H_t / E_t)             # 主口径，现金日也在平均分母
cap_share  = Σ X^H_t / Σ X_t                 # 已投入资金的纯度
cap_conf   = Σ X^(H,confirmed)_t / Σ X^confirmed_t
```

交易 pnl、胜率和笔数按首次开仓年；资金按实际日历年（含带入仓）；段覆盖与 capture 按 first 年。年度权益收益包含融资、跨年估值，不能与按开仓年归属的 H/O pnl 混称。前 10 赢单按实际已平仓整笔 pnl 排序，只有窗口内 T1 净贡献 >0 的笔数才计“他的段”；逐笔 H 金额同时公开，不能把峰后独自盈利当作段内赢单。

### 12.1 唯一的点名接口

`Study.build` 组合 `universe → signal → entries / trade / regime → allocate`，输出沿用 `(entries, Rules, mask, pool)`。新交易员实现 `arrays`、`universe`、`signal`、`trade`；特殊入场才覆盖 `entries`。共享 `allocate` 通过 `allocation.py` 处理10日冷却、候选截断、成功开仓名额、同时持仓与弱仓换仓。账户引擎仍负责成交、规模计算及记账。

`signal(A, pool, cfg)` 返回 `{日历下标: [code, ...]}`，包括暖机、空夜和末夜。它是 S 与分配共读的唯一有序点名。默认执行是次日开盘、前夜低点止损，当天触止损保守退出；`trade.entry='close'` 则当晚收盘确认。无法得到合法止损可以拒绝入场，不能另找未点名的票。

默认冷却10日，只对本次发出的新名启动，跳过不续期，跨年不重置。`allocate.daily_cap='fills'` 限成功开仓，可跳过已持同票；`'offers'` 在账户前截候选队列。这两种语义在共享分配模块中保留。Martin R74 明确沿用 `cooldown=0` 和 `offers`，不能为了统一而改历史成交。

Martin 的 `build_system` 兼容入口现在调用 facade。其 `signal` 包含既有停止规则、市场过滤及 priority，保留原过滤后队列的排序；旧返回 mask 仍是停止规则之前的诊断掩码。S 应直接读 `signal`，不从旧 mask 反推点名。其余覆盖 `build` 的版本由 `Study.legacy` 标识，未迁移前不能报 G3 通过。

配置五节为 `universe / signal / allocate / trade / switch`。`Config` 迭代、序列化的是五节，旧键通过 `cfg['risk']` 等只读别名访问，`flat()` 适配历史实现。分节参数可以同名；有歧义时须按节读取，不能压成旧扁平字典。已有键按所属节提供只读别名，扁平别名与同一节的值冲突会拒绝。旧 round 的浅合并及选择器保留；分节 round 递归合并。

### 12.2 三个 producer，只选一个

regime可以读交易员自己池子里的市场数据，以及本系统在当时已知的点名。不得读他的台账、票名、段表或账户结果；点名反馈必须等所需行情完成才计入，未成熟不能偷看。交易日t的状态只用t−1及以前。P3的复合研究producer在 `studies/martin_luk/p3_signal.py`，按日期推进自己的K=3新名与已成熟两根K反馈，并作市场/状态/点名截断检查；没有改登记版或看板。

通用的 `regime.states(A, spec)` 仍只接下面三种行情定义，输出 int8 日状态、连续 episode、各态天数与段数、完整 spec 及 SHA256，不输出概率。输出数组经 `Study.named(..., 'regime')` 暴露，`ema_inputs` 把状态与分配开关数组交给 `gate.check_lookahead`。门禁也比较逐晚点名的原顺序。

| producer | 已实现定义 |
|---|---|
| `idx_ema`，默认 | 池等权指数低于 EMA50 为 weak；其余高于 EMA21 的1%带为 up，余下 pullback。也支持显式传入 QQQ、IWM 的指数价格，不自动下载或回退 |
| `breadth` | 同一流动性池中，收盘>EMA21>EMA50 为领涨，收盘<EMA21<EMA50 为落后；只数比大于1.5为 up，反比大于1.5为 weak，其余 pullback |
| `smc` | 指数左右各10根分形，右半完成后确认；收盘破最新已确认高点为向上 BOS 或 CHoCH，向下同理；突破仍成立为 up 或 weak，收回突破位内为 pullback |

等权池每个交易日用前一日价格≥5、20日均成交额≥2000万的股票；指数按当日等权回报累乘，高低点是同篮子的高低价格相对前收的等权代理，不是真实指数逐笔高低。2023暖机保留，初始未知结构标 pullback。spec 的冻结日为2026-11-08，SHA 包含定义版本、来源、阈值与lag。换定义就是新的 switch 层，不叠加 producer。

通用映射放 `switch.controls`，最多两个，每个写 `field`、`quote`、`values={up:..., pullback:..., weak:...}`。`quote` 必须逐字存在于本人 RULES_CN。字段仅限 `sides`、`risk_mult`、`setups`、`max_open`、`rotate`。不能表达同类排序或止损宽度。形态开关在共享分配时筛选已点名形态，保留其顺序；这一通用路径的原始 S 点名保持状态盲。`setups` 匹配 entry.kind；可选的 `trade.short` 通过 LongShort 接入，同一方向与规模开关也过滤追加的空单。非 home 市场不启用此映射，报告“未调参”。

研究信号也允许让状态决定名额怎么分到各票档或形态家族，不让状态决定同档中先买哪只，档内沿用预登记家族的固定排序。P3在独立信号模块实现分档名额和固定家族选择，不把新字段塞进通用 `switch.controls`。信号层与仓位层允许paired成对改，主尺仍是覆盖；所有候选共用的仓位规则先冻结，不能看账户后改信号首选。

稳定性逐项扰动：EMA长度±20%，带宽±50%，分形长度±2；breadth只数比±20%。`stability` 报每项日重合率及各状态交并比，最低日重合率须≥90%。这不是概率或置信区间，未达标只说明该定义不稳定。

### 12.3 观测到什么，就验证什么

G2 逐状态检验，统计单位是 episode。调用者在预登记里固定一个本人行为指标，传带日历下标的 `observations`，由 `g2` 按段聚合。每状态至少3个有交易 episode、15笔本人交易才作数据判定；整段摘要置换用固定种子，p<0.1且至少两段同向。全体 episode 逐一留出。训练段报整段置换；留出段的指标与其余其他状态均值相比，至少两段和训练方向一致。逐折数字全报，不能挑好的一段。

无样本或样本不足的状态是“未观测”。只要无未来函数和定义稳定性过关、每个映射都有原话，`permitted` 允许保留该状态规则并继续下游。冻结后前向记录验证该推测，不能写“已复刻他的弱市行为”。有样本状态不过仍挡住下游。

效果归因还须报告关掉 Switch 且匹配平均敞口的对照；`pipeline.exposure_scale` 给出同平均敞口的全局倍数，不自动运行新账户。本轮 P1 只描述三种标签，不选择 Switch、不测候选收益。

## 13. 七道卡子的工件与允许动作

`pipeline.g0` 到 `g6` 返回 `status / reason / numbers`，具体通过线见 SKILL 的七行表。G0 的 manifest 包含 `files`，按 trades、legs、split 各给相对 study 根的路径与 SHA；split JSON 分别给 `select`、`validate` 的起止日。`claims` 按已使用的节列原话、出处和 timestamp，未启用的 switch 可不填，视频来源也可直接含时间戳；`public` 逐项给 value 与 source，未公开的 value 为 null。参照 G1 用 `is_reference=True` 先查自身，再给其他系统作参照。G1 消费既有四个 `gate.check_*` 的完整结果、参照 G1 结果及源码和数据指纹，不把“未检查”当过关。

G3 的 `folds[年份]` 每折给已冻结的 `picks`、`trained_years`、`model_sha`、样本属性，可选 ranks。三年逐折使用 S0 原函数 K=3、10日冷却，覆盖按首锚点年；计算全日历后再读留出年，跨年冷却及跨年合格夜都保留。另用相同点名计算不限K的新名均数≤5，避免宽名单经 K=3 截断后把宽度门槛变成恒真。主留出覆盖≥80%；其他两折也全报并报告均值，缺模型记未观测，不能新增拟合来填格子。`upper_bound` 是开轮前池与合格窗口的可达上限，不足80%就回上游。

G4、G5 按 episode 留一，读同一冻结策略的事实，不重新拟合。G4 按首次开仓所属 episode 分交易，报留出段与其余段的已平仓笔数、胜率、盈亏比和持有。G5 按实际日历段分账户回报，报该段与剔除该段的复合收益；这只是整段剔除描述，不假装删除交易后重配资金。完整年度硬线仍在全账上查，不能把一个短 episode 当作完整年比较52笔。

| 最早未通过卡子 | `allowed_actions` 允许 | 禁止 |
|---|---|---|
| G0 | sources | 进入收益逼近 |
| G1 | data、engine | 改策略解释坏数据 |
| G2 | switch | 调个股排序、止损或账户 |
| G3 | 主改universe、signal；可paired改allocate、trade，选择仍看覆盖 | 用下游收益代替上游覆盖 |
| G4 | allocate、trade | 放宽覆盖或改段表 |
| G5 | diagnose | 无新机制就继续开轮；先定位并重开对应 G3/G4 证据 |
| G6 | freeze | 未经用户同意登记新冻结版 |

新 round 示例：

```json
{
  "layer": "signal",
  "sections_changed": ["signal"],
  "upper_bound": 0.9,
  "pipeline": "reports/pipeline.json",
  "base": ["", "base"],
  "ref": "BASE",
  "candidates": {"A": {"signal": {"rank": "adr"}}}
}
```

`validate_round` 对比实际配置差异，校验每个候选只改声明层。成对改还要 `paired: true`、`mechanism` 说明和准确的 sections_changed。G3未过时，primary layer仍须在universe/signal，另声明 `selection_layer` 与该层相同、`selection_metric` 为上游主尺，才可同时修改allocate/trade；资料、工程等更早卡子仍阻止越层。`allowed_actions` 为G3另列 `paired_downstream`。这些是声明校验，不能替代对实际选择代码的核对；P3以覆盖选择先落chosen、后揭2026和运行账户保证，未声称所有旧选择器自动按S选方案。`Study.round` 在加载行情前读卡子 JSON 并校验，拒绝新轮次把 placebo 用作否决条件。`legacy_rounds.json` 是 P1 开始时已有轮次的路径与 SHA，原文件兼容；新文件或改写的旧文件不享受豁免。

按年份留一的信号与按 episode 留一的交易都只是稳定性核对。已反复看过的2026只标“留出*”；唯一独立样本外是 G6 后逐日保留的 forward。G6 检查用户同意、三市场、robust报告、指纹、登记和日期一致性，不自动修改登记系统。
